## 계획에서 달라진 것

- 부채꼴: 스포트 빛으로 만들었더니 원뿔 가장자리와 둘레 빛이 2D 규칙보다 일찍 어두워져 일치율이 91.6%였다. 계획서의 대안대로 **전방향 빛 하나가 벽 그림자만 맡고, 부채꼴·둘레 원은 지형 셰이더가 2D 규칙과 같은 모양으로 계산**하게 바꿨다 (98.5%).
  - 언데드 시야를 넣을 때는 셰이더가 빛마다 다른 모양을 알아야 한다. 전체 이전의 시야 단계에서 정한다.
- 앞벽: 잘라낸 자리에 낮은 윗면을 깔았다 (없으면 구멍처럼 보인다).

## 도트 1:1과 바닥 떨림

| 설정 | 그림이 원본과 같은 픽셀 | 그림 세로 배율 (가운데 / 화면 위 / 화면 아래 / 옆) | 바닥 떨림: 가장 낮은 일치 |
|---|---|---|---|
| 직교 0도 | 100% | 1.00 / 1.00 / 1.00 / 1.00 | 100% |
| 원근 30, 0도 | 75% | 1.09 / 1.30 / 0.65 / 1.31 | 100% |
| 원근 35, 0도 | 72% | 1.11 / 1.34 / 0.54 / 1.40 | 97.5% |
| 원근 40, 0도 | 72% | 1.13 / 1.38 / 0.40 / 1.51 | 97.5% |
| 직교 45도 | 100% | 1.00 / 1.00 / 1.00 / 1.00 | 100% |
| 원근 30, 45도 | 78% | 1.09 / 1.30 / 0.65 / 1.31 | 99.5% |
| 원근 35, 45도 | 75% | 1.11 / 1.34 / 0.54 / 1.40 | 99.4% |
| 원근 40, 45도 | 73% | 1.13 / 1.38 / 0.40 / 1.51 | 99.3% |

떨림이 없으면 100%다 (기준 98%). 화면 위 240×80 영역에서 잰 값이다.

- **원근에서는 도트 1:1이 깨진다.** 화면 가운데에서도 약 72~78%만 같은 픽셀이다.
- **세로로 세운 그림은 화면 위치에 따라 납작해지거나 늘어난다.** 원근 35도에서 화면 아래쪽 몬스터는 키가 0.54배, 위쪽은 1.34배다. 화각이 클수록 심하다. 제안: 그림의 세로 크기를 프레임마다 화면 높이에 맞춰 보정한다 (구현 안 함).
- 바닥 떨림은 원근에서도 작다. 35·40도 0도에서만 기준(98%)에 조금 못 미치는 순간이 있었다 (평균 99.8% 이상).

## 45도에서 벽 가림이 줄어드는가

화면에 든 바닥 중 벽에 가린 비율. 네크로맨서를 무작위 자리 40곳에 세워 계산했다. 처음 낸 값은 표본 점이 칸 격자에 맞아서 45도를 0으로 잘못 냈고, 위치를 흩뜨려 다시 쟀다.

| 얕은 굴 2배 맵 | 0도 | 45도 |
|---|---|---|
| 원근 35: 화면의 바닥 | 3.0% | 2.9% |
| 원근 35: 네크로맨서 둘레 4칸 | 1.9% | 1.8% |
| 원근 35: 동서로 뻗은 좁은 길 (남북 폭 3칸 이하) | 24.6% | 22.9% |
| 원근 35: 남북으로 뻗은 좁은 길 | 21.3% | 22.8% |

시제품 굴(동서 길목 하나): 0도 24.0% → 45도 17.1%.

**실제 맵에서는 45도로 돌려도 벽 가림이 거의 줄지 않는다.** 시제품 굴의 차이는 길목이 동서로 뻗은 하나뿐이어서 생겼다. 실제 맵에는 동서·남북 길목이 비슷하게 있어 평균은 같다. 45도를 쓸지는 벽 가림이 아니라 보는 맛으로 정하면 된다.

## 팔레트: 어두운 단계 4개 (`proto_25d/palette_dark_steps.hex`)

# 4차 결과 (그림 세로 보정)

명령: `bash tools/godot.sh --path . -s tests/proto/check_view_3d.gd -- --pixels`. 그림의 세로 크기를 프레임마다 맞추고, 그림 위치를 화면 픽셀에 맞췄다.

| 원근 30도, 45도 회전 | 가로 배율 | 세로 배율 | 원본과 같은 픽셀 |
|---|---|---|---|
| 네크로맨서 (화면 가운데) | - | - | 98% (보정 전 81%) |
| 쥐, 가운데 옆 (1.5칸) | 1.00 | 1.00 | 66% |
| 쥐, 화면 위 | 0.91 | 1.00 | 71% |
| 쥐, 화면 아래 | 1.10 | 1.00 | 52% |
| 쥐, 화면 옆 (7칸) | 1.00 | 1.00 | 25% |

직교에서는 같은 쥐가 어디서나 93%, 네크로맨서 100%다.

- 세로 배율은 모든 위치에서 1.00이 됐다 (보정 전 0.59~1.30).
- 남은 차이의 원인 (계산): 원근에서 수직선은 화면 아래쪽 한 점으로 모인다. 화각 30도·기울기 60도에서 그 점은 화면 가운데에서 약 388px 아래다. 세워 둔 그림이 화면 옆(가운데에서 224px)에서는 약 30도, 1.5칸 옆에서는 약 7도 기운다. 가로는 깊이에 따라 0.91~1.10배다.
- **제안** (구현 안 함): 그림을 화면과 평행한 사각형으로 그리면 기울지 않는다. 대신 머리가 북쪽 벽을 뚫는 문제(계획서 문제점 7)를 다시 봐야 한다.

| | 북쪽 벽 | 서쪽 벽 | 북서 모서리 | 기둥 남쪽 면 |
|---|---|---|---|---|
| 네크로맨서 | 100% | 100% | 100% | 100% |
| 쥐 | 100% | 100% | 100% | 100% |

- 쥐가 93%였던 이유: 발밑 기준선보다 아래로 그려지는 픽셀 22개(불투명 301개 중)가 바닥에 가렸다. 그림의 깊이만 카메라 쪽으로 0.3단위 당겨 고쳤다 (`View3D.sprite_depth_bias`). 이제 화면 어디서나 100%다.
- 앞쪽 벽에는 여전히 가려진다 (앞벽 처리를 끄고 76%).

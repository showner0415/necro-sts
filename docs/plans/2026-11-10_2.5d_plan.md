# 2.5D 전환 계획 (2026-11-10)

상태: **계획. 코드는 바꾸지 않았다.** 아래 값은 모두 제안이며, 사용자가 정한 것은 "정한 것"에만 적었다.

## 정한 것 (사용자)

- 캐릭터는 2D 도트 그림, 맵은 3D. 높이는 처음엔 게임에 영향 없음 (바닥 평평, 3D는 보이는 모습에만)
- 게임 규칙(이동, 충돌, 길찾기, 시야 판정, 테스트, 측정 봇)은 2D 평면 그대로 두고 화면만 3D로 그린다
- 카메라 각도 고정. 직교 우선, 시제품에서 원근과 비교
- 3D를 640×360으로 그려 정수배로 키움. 팔레트 후처리는 있는 것과 없는 것을 비교

## 1. 구조와 문제점

### 구조

지금의 2D 씬은 "규칙 세계"로 그대로 둔다. 그 위에 보이는 것만 맡는 3D 층(`View3D`)을 얹어, 프레임마다 2D 노드를 읽어서 3D 노드를 옮긴다. 3D 층은 규칙에 아무것도 돌려주지 않는다. 유일한 예외는 마우스 조준이다.

- 좌표: 2D (x, y) → 3D (x/32, 높이, y/32). 타일 1칸 = 3D 1단위
- 지금 프로젝트는 창 늘리기가 `viewport`라서 루트 뷰포트가 이미 640×360이다. 3D를 여기에 그리면 SubViewport 없이 그대로 저해상도로 그려지고 정수배로 커진다
- 헤드리스(테스트·측정)에서는 3D 층을 만들지 않는다. 측정 속도와 결과가 그대로다
- 2D 그리기는 숨겨 두되 개발용 키로 3D 위에 겹쳐 볼 수 있게 한다. 규칙과 화면이 어긋났을 때 바로 보인다

이 방향이 맞다고 본다. 게임 규칙 파일 대부분과 테스트 자산을 지킨다. 다만 아래 문제가 있다. 위쪽일수록 중요하다.

### 문제점

| # | 문제 | 내용 | 대응 |
|---|---|---|---|
| 1 | **2D 좌표에 가짜 높이가 섞여 있다** | 몸 가운데는 발밑에서 y로 −6 (`get_body_center`), 몬스터도 `PlaceholderBody.center`, 돌은 `throw_height` 6과 `ground_offset`. 2D에서는 "위로 그린 것"이지만 평면으로 보면 바닥에서 북쪽으로 6px 옮겨진 자리다. 충돌 원의 가운데도 발밑보다 6px 북쪽이다 | 규칙은 그대로 두고, 3D 층이 종류별로 되돌려 그린다 (탄: 평면 y + 6 자리에 높이 6). 시제품에서 확인 |
| 2 | **바닥 위치로 조준하면 몸을 눌러도 그 뒤를 쏜다** | 그림은 바닥에서 위로 서 있다. 몬스터 몸을 클릭하면 광선은 그 뒤쪽 바닥에 닿는다. 60도에서 높이 16px을 누르면 약 9px 뒤다 | 바닥이 아니라 **탄 높이의 평면**과 만나는 점으로 조준한다. 맞는지는 시제품 통과 기준에 넣었다 |
| 3 | **남쪽 벽이 뒤를 가린다** | 벽 높이 32, 각도 60도면 벽 북쪽 바닥 18.5px이 안 보인다. 2칸 길목(64px)의 29%다. 벽에 붙은 캐릭터는 아래 16px이 가려지고 키 작은 쥐는 많이 가린다. 규칙은 "보임"인데 화면에서는 안 보이는 경우가 생긴다 | 벽 높이를 낮게 시작. 시제품에서 재고, 심하면 앞쪽 벽을 낮추거나 투명하게 |
| 4 | **세로 화면 범위와 속도감이 바뀐다** | 바닥 세로가 sin(각도)배로 줄어 화면에 더 많이 보인다 (지금 11.25칸 → 60도 13칸). 남북 이동이 화면에서 느려 보이고, 화면의 45도는 바닥의 45도가 아니다 | 규칙은 그대로. "화면 안"을 재는 시나리오와 맵 의도(전망 바위 등)를 다시 본다. 예고 읽기는 사람이 확인 |
| 5 | **시야 판정과 그림자가 다른 계산이다** | 몬스터가 보이는지는 `VisionRules`(타일)로, 밝기는 3D 빛 그림자로 정한다. 모서리에서 어긋나면 어두운 곳에 몬스터가 보일 수 있다 | 빛을 벽보다 낮게 두어 2D와 같은 그림자를 만든다. 일치율을 재서 통과 기준으로 삼는다 |
| 6 | **3D 빛은 부채꼴이 아니다** | 스포트 빛은 원뿔이고 바닥에는 비스듬히 닿아 멀수록 어두워진다 | 빛을 낮게(12px) 수평으로 두면 바닥에 닿는 모양이 70도 부채꼴에 가깝다. 거리 감쇠와 입사각은 지형 셰이더에서 뺀다. 안 되면 전방향 빛 + 셰이더 부채꼴 마스크로 |
| 7 | **빌보드가 벽에 파묻힌다** | 카메라를 정면으로 보는 빌보드는 머리가 북쪽으로 기울어 북쪽 벽을 뚫는다 (32px 그림이 약 28px) | 수직으로 세우고 세로만 1/cos(각도)배 (60도면 2배). 직교에서는 화면에서 정확히 1:1 픽셀이다 |
| 8 | **테스트가 화면을 보증하지 못한다** | 578개가 통과해도 3D 층이 틀릴 수 있다. 테스트 입력(`aim_mouse_at`)은 2D 변환을 쓴다 | 조준 경로를 한 곳으로 모으고, 창을 띄우는 화면 검사(동기화, 조준, 시야 일치)를 따로 만든다 |
| 9 | **픽셀이 떨린다** | 저해상도 3D에서 카메라가 소수 위치로 움직이면 바닥 무늬가 꿈틀거린다 | 카메라와 빌보드를 화면 픽셀 격자에 맞춘다. 안티에일리어싱 끔, 재질은 전부 Nearest |
| 10 | **그리는 코드가 넓게 퍼져 있다** | `_draw`가 14개 파일에 있고 돌진 선·돌 그림자·탈출 원처럼 바닥에 그리는 것이 많다 | 바닥 표시는 2D 캔버스(SubViewport)에 그대로 그려 바닥에 입힌다. 코드를 살릴 수 있다 |
| 11 | **성능** | 2배 맵은 480×232칸. 시야 빛은 플레이어 + 언데드마다 그림자 빛 하나 | 벽 메시를 구역으로 나눈다. 언데드 8마리로 잰다 |
| 12 | **나중에 높이를 넣기 어렵다** | 평면 규칙이라 경사·점프·높이 판정이 게임에 필요해지면 이 구조는 맞지 않는다. 층을 나누는 정도까지만 된다 | 지금 결정과 맞다. 높이가 규칙이 되는 순간 다시 판단한다 |

맞았을 때 번쩍임(`modulate` 3배)은 3D에서 값이 잘려 안 보일 수 있어 그림 재질에서 따로 처리한다.

## 2. 브랜치 합치기

실제로 합쳐서 전체 테스트를 돌려 봤다 (임시 폴더, 지금은 지움).

| 브랜치 | main 기준 | 합치기 충돌 | `bash tests/run_all.sh` |
|---|---|---|---|
| vision | 뒤처짐 0, 앞섬 3 | 없음 (빨리 감기) | vision + map-2x: 통과 513, `scenario_shallow_cave.gd` 실패 |
| map-2x | 뒤처짐 2, 앞섬 6 | 없음 | 단독으로도 같은 실패 |
| monster-ai (vision 포함) | 뒤처짐 0, 앞섬 15 | map-2x와 없음 | monster-ai + map-2x: 통과 560, 같은 실패 |

실패 내용: "굴 역할 찾기: 못 찾은 역할 egg". **합치기가 아니라 map-2x에 원래 있는 실패다.** 시나리오가 여기서 멈추므로 뒤 단계(걷기 시간, 바위, 탈출)는 합친 상태에서 돌지 않았다. 또 설계 문서의 2배 맵 계획은 몬스터 21 → 42인데 지금 맵의 몬스터는 21마리다.

제안:

1. `vision`을 main에 빨리 감기로 합치고 push한다.
2. `map-2x`는 그 브랜치에서 실패를 고치고, 몬스터·상자 2배를 지금 할지 정한다. `run_all.sh`가 통과하면 main에 `--no-ff`로 합친다. 맵 씬은 PNG에서 다시 만들어 맞는지 확인한다.
3. `monster-ai`도 시제품 전에 main에 합치기를 권한다. 3D 작업이 `monster.gd`, `necromancer.gd`를 만지므로 오래 떨어져 있을수록 충돌이 커진다. 이 브랜치는 테스트가 통과한 상태다.

시제품은 굴 하나만 쓰므로 map-2x를 기다리지 않아도 된다.

## 3. 시제품 (`proto-2.5d` 브랜치)

main에서 딴다. 기존 씬은 바꾸지 않고 시제품 씬을 따로 만든다. 게임 쪽에서 고치는 것은 조준 위치를 읽는 곳 한 군데다.

### 만드는 것

| 항목 | 내용 |
|---|---|
| 굴 | 얕은 굴의 쥐 둥지 크기 굴 하나 + 2칸 길목 + 기둥 하나. 2D 벽 격자(`wall_grid()`)에서 3D 벽·바닥을 만든다 |
| 네크로맨서 | 지금의 `SpriteFrames`를 그대로 쓴다. 숨긴 2D 스프라이트의 애니메이션·프레임을 3D 스프라이트에 복사해서 8방향·걷기·거꾸로 걷기 규칙을 다시 만들지 않는다 |
| 카메라 | 네크로맨서를 따라가고 각도 고정, 픽셀 격자에 맞춤 |
| 마우스 조준 | 화면 광선과 탄 높이 평면의 교점 → 2D 위치 |
| 시야 | 3D 빛과 벽 그림자, 부채꼴 70도(완전히 밝은 46도), 둘레 원, 지형만 어둡게(0.4). 몸은 빛의 영향을 받지 않고 원래 색 |
| 쥐 | 지금의 몬스터 씬과 데이터 그대로. 그림은 확정된 쥐 그림 |
| 비교 키 | 직교 ↔ 원근, 팔레트 후처리 켬 ↔ 끔, 2D 겹쳐 보기 |

### 제안 값

| 값 | 제안 | 이유 |
|---|---|---|
| 카메라 각도 | **60도** (아래로) | 벽 앞면이 정확히 16px, 가림이 적음 |
| 벽 높이 | **32px (1칸)** | 앞면 16px, 뒤 가림 18.5px |
| 빛 높이 | 12px | 벽보다 낮아 2D와 같은 그림자, 부채꼴 모양 유지 |
| 직교 크기 | 세로 11.25단위 | 그림 1픽셀 = 화면 1픽셀 |
| 원근 | 화각 20도, 거리 약 32단위 | 발밑 평면에서 직교와 같은 크기 |

각도와 벽 높이는 값으로 빼서 바꿔 볼 수 있게 한다.

| 각도 | 바닥 한 칸 세로 | 벽 32 앞면 | 벽 32 뒤 가림 | 벽 48 뒤 가림 | 세로로 보이는 칸 |
|---|---|---|---|---|---|
| 45도 | 22.6px | 22.6px | 32px | 48px | 15.9 |
| 50도 | 24.5px | 20.6px | 26.9px | 40.3px | 14.7 |
| **60도** | **27.7px** | **16px** | **18.5px** | 27.7px | **13.0** |
| 70도 | 30.1px | 10.9px | 11.6px | 17.5px | 12.0 |

원근은 직교보다 불리할 것으로 본다. 깊이마다 그림 크기가 달라져 "픽셀 밀도 통일" 규칙을 지킬 수 없다. 그래도 비교는 보여 준다.

팔레트 후처리는 HUD 아래에 전체 화면 셰이더로 넣는다. 도트 느낌은 좋아질 수 있지만, 어두운 색이 적은 팔레트라 시야 가장자리 그라데이션이 띠처럼 끊길 위험이 있다.

### 통과 기준

스크립트로 재는 것:
1. 직교에서 네크로맨서 그림이 원본 프레임과 픽셀까지 같다
2. 쥐 그림 가운데를 8방향에서 클릭해 쏘면 맞는다
3. 시야 판정과 화면 밝기 일치 95% 이상 (굴 안의 점들을 위치·방향 몇 개에서 비교)
4. 플레이어 + 언데드 빛 8개에서 프레임 시간 (지금 2D +1.05ms와 비교해 보고)
5. 걸을 때 바닥이 꿈틀거리지 않음 (연속 스크린샷)

사용자가 보는 것:
6. 직교 / 원근 비교, 팔레트 켬 / 끔 비교 (네 장을 나란히 + 직접 조작)
7. 조작감, 벽 가림이 답답하지 않은지, 시야가 읽히는지

## 4. 시제품 통과 뒤 전체 이전 순서

단계마다 `run_all.sh`와 스크린샷으로 확인한다.

1. **경계 만들기 (화면 변화 없음)**: 조준 위치를 한 곳으로 모으고 3D 층 뼈대를 넣는다
   - 넣은 것 (2026-11-10): `view_3d/`의 `RegionView3D`(카메라·조준·화면 기준 이동), `ViewSpace`(좌표 규칙), `RegionData.view_3d`(기본 끔, 켠 지역에만 층이 붙음), 테스트의 `aim_mouse_at`이 층을 거치는 경로
2. **지형**: 지역 씬마다 벽 격자에서 3D 지형을 만든다. 2배 맵은 구역으로 나눈다
   - 검사 항목 (사용자 요청, 2026-11-10): 시제품의 반투명 켬·끔 화면 비교에서, 쥐에서 수백 픽셀 떨어진 벽 모서리의 1~4픽셀이 실행마다 다른 자리에서 달라졌다. 원인은 확인하지 못했다
     - 후보: 맞닿은 면의 깊이 겹침 (벽 윗면·앞면과 그림자 전용 메시가 모서리를 공유), 그림자 (전방향 빛의 그림자 지도 해상도·경계 흔들림), 메시 조각 사이의 틈 (사각형이 모서리에서만 만남), 카메라 깊이 방향 위치 (앞서 가기가 프레임 시간을 써서 실행마다 소수점이 다르고, 깊이 방향은 픽셀 격자에 맞추지 않음), 팔레트 후처리 (작은 밝기 차이가 가장 가까운 색의 경계를 넘음)
     - 확인 방법: 시간 간격을 고정하고 같은 장면을 반투명 없이 두 번 찍어 달라지는 픽셀이 있는지 본다. 있으면 그림자 끔, 팔레트 끔, 구역 메시(벽 면을 합친 메시)로 하나씩 바꿔 가며 사라지는 쪽을 찾는다
     - 결과 (2026-11-10, `tests/view_3d/check_wall_flicker.gd`): **원인은 아직 못 찾았고 후보를 좁혔다.**
       - 멈춘 장면을 반복해 찍으면 시제품·새 지형 모두 달라진 픽셀 0 (가변 시간·고정 60fps 모두).
       - 시제품 반투명 검사의 자세를 옮겨 다니면 가변 시간에서만 나온다 (실행의 약 절반). 고정 60fps에서는 3번 모두 0.
       - 같은 픽셀 (579, 190), (558, 182)이 벽 색과 바닥(또는 배경) 색 사이를 오간다. 면의 색이 아니라 면 경계 픽셀의 판정이 뒤집힌다.
       - 팔레트를 꺼도, 시야(그림자)를 꺼도 나온다. 두 후보는 빠졌다.
       - 카메라 깊이를 앞서 가기와 무관하게 고정해도 8번 중 6번 나왔다 (임시로 고쳐 재고 되돌림). 이 후보도 빠졌다.
       - 남은 후보: 프레임 시간에 따라 달라지는 다른 값 (아직 특정 못 함), 경계에 걸친 픽셀의 GPU 판정.

## 5. 몬스터 AI·투사체를 3D 작업과 동시에 해도 되는가

**시제품 동안은 해도 된다. 전체 이전 3~5단계 동안은 멈추기를 권한다.**

- 시제품은 게임 코드를 거의 건드리지 않아 "찾기"·"평소" 같은 규칙 작업(AI 2·3단계)과 겹치지 않는다. 시제품이 실패해도 규칙 작업은 남는다.
- 3~5단계는 `monster.gd`, `undead.gd`, `stone.gd`, 행동의 `draw_overlay`를 고친다. 예고 표시를 함께 바꾸면 충돌과 재작업이 생긴다.
- **보이는 것에 대한 판단은 3D 뒤로 미룬다.** 박쥐 방향 표시 방식, 돌 포물선과 그림자 원, 쥐·고블린 멈춤이 눈에 읽히는지는 화면이 바뀌면 다시 봐야 한다. 세로가 줄어들어 예고 읽기가 달라지기 때문이다. 지금 F5로 보는 것은 참고로만 쓴다.
- 멧돼지 방향 고정 시간 같은 값 조정은 규칙이지만, 측정 봇 변경이 보류라 기준이 없다. 값은 봇 재개 뒤에 정한다.

## 시제품 결정 (사용자, 2026-11-10)

- **3D로 간다.**
- 카메라는 원근. 화각은 30~40도 사이에서 비교한다 (F7).
- 앞벽: 플레이어와 조준점 주변은 잘라내기, 시야 판정상 보이는 물체(몬스터·물건·내 언데드) 앞은 반투명, 시야 밖 물체 때문에 반투명해지면 안 된다, 나머지는 그대로. 전환은 깜빡이지 않게 부드럽게.
- 팔레트는 켜되, 빛 없는 지형에서 벽과 바닥이 구분되도록 어두운 단계를 3~4개 더 넣는다. 최종 결정은 지형 에셋을 만든 뒤에 다시 한다.
- 화면을 맵 기준 45도 돌린 시점을 추가해 0/45도를 비교한다 (F8). 규칙 좌표는 2D 그대로, 이동은 화면 기준, 8방향 그림은 화면 방향 기준.

`docs/art-direction.md`의 시점·기준 규칙은 전체 이전의 해당 단계에서 바꾼다.

## 시제품 뒤 브랜치 (사용자 결정, 2026-11-10)

1. `proto-2.5d`를 main에 `--no-ff`로 합친다. 합쳐도 게임 동작은 2D 그대로다. 게임 코드 변경은 조준·이동·8방향 그림의 연결부뿐이고 기본값에서는 전과 같다.
2. 전체 이전은 main에서 새로 딴 `migrate-2.5d`에서 한다. `proto_25d/`는 참고용으로 두고 정리 단계에서 지운다.
3. main에는 게임을 그대로 실행할 수 있는 단계에서만 합친다. 1단계(경계 만들기)가 끝나면 한 번 합치고, 2~5단계는 화면이 섞이므로 5단계가 끝난 뒤 합친다.
4. 2~5단계 동안 main에 다른 작업이 들어가면, 단계가 끝날 때마다 main을 `migrate-2.5d`로 합쳐 충돌을 작게 나눠 푼다.
5. `migrate-2.5d`는 단계마다 push한다.

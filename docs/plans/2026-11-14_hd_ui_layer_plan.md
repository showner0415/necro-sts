# 고해상도 UI 층 (2026-11-14)

상태: 진행 중 (5단계 기준 세트) (2026-11-16)
브랜치: `hd-ui` (origin/main에서 땀, 사용자 결정 2026-11-16. 합치는 때는 아직 안 정함)

## 목표

게임 화면은 지금처럼 640×360으로 그려 정수 배율로 늘리고, UI만 실제 창 해상도로 그린다. GPT로 그린 UI 그림과 한글이 뭉개지지 않게 하려는 것이다 (사용자가 UI는 꼭 도트일 필요는 없다며 GPT로 그려 보기로 함, 2026-11-14).
이 계획의 1~4단계가 끝나야 `ui-designer` 에이전트가 그림을 붙일 수 있다.
하지 않는 것: UI 그림 그리기(`ui-designer`의 일), UI 배치 바꾸기, 게임 화면의 해상도·카메라·도트 크기 바꾸기.

## 정한 것 (사용자, 2026-11-14)

- UI 그림은 GPT로 그린다. `ui-designer` 에이전트가 다듬어 붙인다.
- 그림은 Codex CLI의 그림 생성으로 ChatGPT 구독 한도 안에서 받는다. API 키는 쓰지 않는다. ChatGPT에서 직접 그려 넣는 방식은 예비로 둔다 (사용자 결정, 2026-11-15. 처음에는 직접 넣기로 했었다)
- Codex를 부를 때 글 모델은 GPT-6.1 Sol, effort는 medium으로 고정한다. 그림 모델은 Codex가 정한다 (사용자 결정, 2026-11-15)
- 게임 화면은 640×360 그대로 두고 UI만 고해상도로 그리는 구조로 간다 (GPT UI를 쓰려고 고른 구조).
- UI 그림은 픽셀 아트 규칙의 예외다. 픽셀 아트는 게임 화면(640×360)에만 적용한다. 단, UI가 게임 화면과 따로 놀지 않게 팔레트 색감과 어두운 분위기는 맞춘다. UI 장식에 네크로맨서·해골(뼈·머리뼈) 모티프는 넣지 않는다. 아이템 아이콘은 예외다 (사용자 결정, 2026-11-15. `docs/art-direction.md`의 "스타일"에도 적었다)
- 이 계획은 뼈대만 먼저 만들고, 구현은 PC의 Claude Code에서 단계별로 한다.
- UI 기준 해상도는 1920×1080이다. UI 그림은 이 크기 기준으로 그린다 (사용자 결정, 2026-11-15. 640×360의 정확히 3배)
- 고른 스타일 시안의 그림과 요청문은 `art_src/ui/style/`에 git으로 올려 두 컴퓨터에서 쓴다 (사용자 결정, 2026-11-15). 다른 UI 그림의 원본 규칙은 4단계에서 정한다.
- 기준 세트 (사용자 결정, 2026-11-16. ui-designer의 비교판 `art_src/ui/inbox/ref_set/compare/`를 보고 고름):
  - 아이콘은 icon_set_3 (아이콘 비교판 4번 줄): 뼈, 쥐·멧돼지·박쥐·고블린 투석병의 머리뼈, 마나 물약. 물약은 아직 데이터에 없지만 뼈색이 아닌 아이콘의 색 기준으로 넣는다. 에이전트 추천은 icon_set_2였다.
  - 창 틀은 frame_1 (모서리가 불룩한 것). 가운데는 그림에서 쓰지 않고 테마 판(181425)이 그린다 (`draw_center = false`).
  - 9-slice 변은 반복으로 한다 (변을 정수 번 반복하되 딱 맞게 조금 늘림. 비교판에서 본 방식). 추천은 이음매가 없는 늘리기였다.
  - 규격은 제안대로: 아이콘은 게임에서 72×72로 보이고 96×96 칸의 가운데에 놓는다. 파일은 144×144 (투명 테두리를 자르고 긴 변을 맞춤), 외곽선 없음, 빛은 왼쪽 위. 창 틀은 띠 36px(게임 12px)이 되게 줄인다.
  - 요청문 틀은 판 1 안대로 (고정 스타일 문장 + 아이콘 덧붙임 + 뼈·머리뼈 색 문장 + 늘 붙이는 말, 함께 넣을 그림은 기준 세트 아이콘 가운데 형태가 가까운 2장). 원문은 `docs/ui-style.md`의 "요청문 틀"에 옮긴다.

## 문제와 위험

| # | 문제 | 내용 | 대응 |
|---|---|---|---|
| 1 | 지금은 모든 것이 640×360에 그려진다 | `project.godot`의 늘리기 방식이 `viewport`라 UI(CanvasLayer)도 640×360으로 그려져 늘어난다 | 1단계에서 방식을 골라 시제품으로 확인한다 |
| 2 | UI가 지역 씬 안에 있다 | HUD·인벤토리 등이 지역 씬마다 들어 있고(`regions/base.tscn` 등), 얕은 굴은 `tools/map_from_png.gd`가 만든다. 지역은 `regions/region.gd`의 `change_scene_to_file`로 바뀐다 | 1단계에서 UI를 지역 씬에 둔 채 고해상도로 그릴 수 있는지 먼저 본다 (아래 제안 A) |
| 3 | 조준이 마우스 좌표에 기댄다 | `view_3d/region_view_3d.gd`가 `get_viewport().get_mouse_position()`과 카메라 광선으로 조준점을 구한다. 게임 화면의 뷰포트가 바뀌면 좌표가 어긋날 수 있다 | 2단계 통과 기준에 조준 시나리오를 넣는다. 조작감은 사용자가 직접 확인한다 |
| 4 | 시나리오가 UI 좌표를 640 기준으로 흉내 낸다 | `tests/scenario_test.gd`의 `ui_to_window()`와 "헤드리스 창 64×64 → UI 좌표 640×640" 규칙(CLAUDE.md)이 바뀐다 | 3단계에서 좌표 변환을 한 곳에서 고치고 모든 시나리오를 돌린다 |
| 5 | 스크린샷이 루트 화면만 찍는다 | `tools/screenshot.gd`가 `root.get_texture()`를 저장한다. 구조에 따라 UI나 게임 화면이 빠지거나 크기가 바뀐다 | 3단계에서 고치고, 3D 화면 검사(`bash tests/run_view_3d.sh`)를 다시 돌린다 |
| 6 | GPT 그림은 팔레트 검사에 걸린다 | `run_all.sh`가 `assets/` 전체를 Endesga 32로 검사한다. GPT 그림은 색이 수천 개다 | 4단계에서 고해상도 UI 그림 폴더를 정하고 그 폴더만 검사에서 뺀다 (사용자 결정 필요) |
| 7 | 에셋 재생성 규칙과 맞지 않는다 | CLAUDE.md는 "생성 파라미터로 다시 만든다"인데 GPT는 같은 요청에도 다른 그림을 낸다 | 4단계에서 UI 그림만 "요청문과 받은 원본을 `art_src/ui/`에 저장한다"로 바꾼다 (사용자 결정 필요) |

## 제안 값 (정하지 않음)

| 값 | 제안 | 이유 |
|---|---|---|
| 방식 | A: UI의 CanvasLayer가 루트 창에 그려지게 하기 (`custom_viewport`) / B: 게임 화면을 SubViewport로 옮기고 UI를 그 바깥에 두기 | A가 되면 지역 씬과 맵 변환 도구를 거의 안 고친다. 입력이 제대로 가는지 모르므로 1단계에서 먼저 시험한다. 안 되면 B |
| UI 기준 해상도 | 1920×1080 (UI 그림은 이 크기 기준으로 그린다). 사용자 확정, 2026-11-15 (위 "정한 것") | 640×360의 정확히 3배라 게임 화면과 배율이 맞는다 |
| 한글 글꼴 | Pretendard 또는 Noto Sans KR (둘 다 무료 공개 글꼴, OFL) | 작은 글자에서도 읽기 쉽다. 도트 느낌을 원하면 갈무리(도트 글꼴) |
| 고해상도 UI 그림 폴더 | `assets/ui_hd/` (팔레트 검사 예외) | 도트 UI(`assets/ui/aim_cursor/`)와 섞이지 않게 |
| 공용 테마 | `ui/theme/` 아래 테마 파일 하나 | 창 틀·버튼을 화면마다 따로 두지 않게 |

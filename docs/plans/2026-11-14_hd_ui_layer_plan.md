# 고해상도 UI 층 (2026-11-14)

상태: 끝남 (1~5단계 끝냄. 브랜치를 합치는 때와 보류로 넘긴 것은 아래) (2026-11-17)
브랜치: `hd-ui` (origin/main에서 땀, 사용자 결정 2026-11-16. 5단계를 끝낸 뒤 main에 합치기로 함, 사용자 결정 2026-11-17, 아래 "정한 것")

## 목표

게임 화면은 지금처럼 640×360으로 그려 정수 배율로 늘리고, UI만 실제 창 해상도로 그린다. GPT로 그린 UI 그림과 한글이 뭉개지지 않게 하려는 것이다 (사용자가 UI는 꼭 도트일 필요는 없다며 GPT로 그려 보기로 함, 2026-11-14).
이 계획의 1~4단계가 끝나야 `ui-designer` 에이전트가 그림을 붙일 수 있다.
하지 않는 것: UI 그림 그리기(`ui-designer`의 일), UI 배치 바꾸기(예외: 창고를 열면 인벤토리 창 왼쪽이 화면 밖으로 나가는 것은 5단계에서 그림을 붙이기 전에 고친다, 사용자 결정 2026-11-16), 게임 화면의 해상도·카메라·도트 크기 바꾸기.

## 정한 것 (사용자, 2026-11-14)

- UI 그림은 GPT로 그린다. `ui-designer` 에이전트가 다듬어 붙인다.
- 그림은 Codex CLI의 그림 생성으로 ChatGPT 구독 한도 안에서 받는다. API 키는 쓰지 않는다. ChatGPT에서 직접 그려 넣는 방식은 예비로 둔다 (사용자 결정, 2026-11-15. 처음에는 직접 넣기로 했었다)
- Codex를 부를 때 글 모델은 GPT-6.1 Sol, effort는 medium으로 고정한다. 그림 모델은 Codex가 정한다 (사용자 결정, 2026-11-15)
- 게임 화면은 640×360 그대로 두고 UI만 고해상도로 그리는 구조로 간다 (GPT UI를 쓰려고 고른 구조).
- UI 그림은 픽셀 아트 규칙의 예외다. 픽셀 아트는 게임 화면(640×360)에만 적용한다. 단, UI가 게임 화면과 따로 놀지 않게 팔레트 색감과 어두운 분위기는 맞춘다. UI 장식에 네크로맨서·해골(뼈·머리뼈) 모티프는 넣지 않는다. 아이템 아이콘은 예외다 (사용자 결정, 2026-11-15. `docs/art-direction.md`의 "스타일"에도 적었다)
- 이 계획은 뼈대만 먼저 만들고, 구현은 PC의 Claude Code에서 단계별로 한다.
- UI 기준 해상도는 1920×1080이다. UI 그림은 이 크기 기준으로 그린다 (사용자 결정, 2026-11-15. 640×360의 정확히 3배)
- 고른 스타일 시안의 그림과 요청문은 `art_src/ui/style/`에 git으로 올려 두 컴퓨터에서 쓴다 (사용자 결정, 2026-11-15). 다른 UI 그림의 원본 규칙은 4단계에서 정했다 (아래 "원본 규칙" 줄).
- 기준 세트 (사용자 결정, 2026-11-16. ui-designer의 비교판 `art_src/ui/inbox/ref_set/compare/`를 보고 고름):
  - 아이콘은 icon_set_3 (아이콘 비교판 4번 줄): 뼈, 쥐·멧돼지·박쥐·고블린 투석병의 머리뼈, 마나 물약. 물약은 아직 데이터에 없지만 뼈색이 아닌 아이콘의 색 기준으로 넣는다. 에이전트 추천은 icon_set_2였다.
  - 창 틀은 frame_1 (모서리가 불룩한 것). 가운데는 그림에서 쓰지 않고 테마 판(181425)이 그린다 (`draw_center = false`).
  - 9-slice 변은 반복으로 한다 (변을 정수 번 반복하되 딱 맞게 조금 늘림. 비교판에서 본 방식). 추천은 이음매가 없는 늘리기였다.
  - 규격은 제안대로: 아이콘은 게임에서 72×72로 보이고 96×96 칸의 가운데에 놓는다. 파일은 144×144 (투명 테두리를 자르고 긴 변을 맞춤), 외곽선 없음, 빛은 왼쪽 위. 창 틀은 띠 36px(게임 12px)이 되게 줄인다.
  - 요청문 틀은 판 1 안대로 (고정 스타일 문장 + 아이콘 덧붙임 + 뼈·머리뼈 색 문장 + 늘 붙이는 말, 함께 넣을 그림은 기준 세트 아이콘 가운데 형태가 가까운 2장). 원문은 `docs/ui-style.md`의 "요청문 틀"에 옮긴다.
- 방식은 B 변형이다: 3D 화면 층만 `GameScreen`의 SubViewport(내부 해상도)에 그려 늘리고, 루트 창은 canvas_items로 HUD·창을 실제 해상도로 그린다 (사용자 결정, 2026-11-16. 1단계 시제품을 보고 고름. 제안 A는 시험하지 않았다).
  - 기본으로 켜는 것(project.godot의 늘리기 방식을 canvas_items로, `--hd_ui` 플래그 정리)은 스크린샷 도구·3D 화면 검사를 고치는 3단계와 함께 한다. 그때까지는 `--hd_ui`로만 켠다 (사용자 결정, 2026-11-16. 3단계를 3·3b로 나눠, 기본 켜기는 3단계에서 하고 스크린샷 도구는 3b단계로 넘김. 나누는 초안을 사용자가 승인함, 2026-11-16). 그때 `docs/art-direction.md` "확정된 규칙"의 "늘리기 방식 `viewport`" 줄도 고친다.
- UI 배치 좌표는 640×360 기준 그대로 둔다. 위 "UI 기준 해상도 1920×1080"은 그림의 기준이고, 그림은 1/3 크기로 놓는다 (사용자 결정, 2026-11-16).
- 3D 화면 검사(`bash tests/run_view_3d.sh`)를 막는 원래 오류(`monsters/monster_pack.gd:394`, 지워진 몬스터를 무리가 읽음)는 이 브랜치에서 따로 커밋으로 고친다 (사용자 결정, 2026-11-16).
- 몸 곁 안내 글자("[F] 창고")와 스태미나 도넛(ScreenAnchors 층)은 루트 창에 실제 해상도로 그린다. 자리는 지금처럼 3D 화면의 몸 곁이다 (사용자 결정, 2026-11-16. 비교판 `compare/2026-11-16_prompt-donut-place/`의 2번을 고름: GameScreen 안 640 도트 / 둘 다 루트 / 글자만 루트를 거점 상자 앞에서 견줌. 비교판은 저장소에 남기지 않음. 처음에는 "4단계 때 비교판으로 본다. 그때까지는 GameScreen 안에서 640 도트"였다).
- 스크린샷 도구(`tools/screenshot.gd`, `tools/record_vision_sequence.gd`, `tools/shot_view_3d_combat.gd`)는 기본으로 창 그림(UI 포함, 창 해상도)을 저장하고, 인자를 주면 게임 화면(GameScreen, 내부 해상도, UI 없음)만 저장한다 (사용자 결정, 2026-11-16. 3단계에서 찍은 거점 그림을 보고 고름).
  - 인자는 `--game_only`다. 3D 층이 없는 화면(`--view_2d`)에서 `--game_only`를 주면 찍지 않고 종료 코드 2로 끝낸다. 전투 장면 촬영의 2배 그림(`_x2`)은 `--game_only`일 때만 만든다. 3D 화면만 견줄 때(전후 비교, compare-variants의 `shoot` 인자)는 `--game_only`를 쓴다 (사용자 결정, 2026-11-16. 3b단계에서 제안한 셋을 그대로 고름).
- 평면 보기(`--view_2d`)는 그대로 둔다: 3D 층이 없어 2D 세계를 루트에 실제 해상도로 그린다 (사용자 결정, 2026-11-16. 디버그 보기이고 맵 전체 그림에도 쓴다. 정지 화면에서 도트가 깨지지 않음을 보고 고름).
- 5단계에서 인벤토리 창에 그림을 붙이기 전에, 창고를 열면 인벤토리 창 왼쪽이 화면 밖으로 나가는 배치를 고치는 작은 단계를 따로 둔다 (사용자 결정, 2026-11-16. 틀의 네 모서리를 모두 보고 판정하려고).
- 5단계 화면 확인: Claude는 1280×720 스크린샷을 찍어 보고, UI 기준 해상도 1920×1080(배율 3)은 사용자가 창을 최대화해 직접 본다 (사용자 결정, 2026-11-16. 이 모니터에서는 1920×1080 스크린샷이 찍히지 않음).
- 인벤토리 창 자리: 사용자가 에디터에서 옮겨 둔 왼쪽 자리(커밋 90bb30f)를 지키되, 창 왼쪽 끝이 화면 안에 들어오게 화면 왼쪽 여백 4에서 오른쪽으로 커지게 한다. 창고·상자·수리 창과 함께 열 때와 인벤토리만 열 때 같은 자리다 (사용자 결정, 2026-11-17. 처음에는 창고 창과 거울처럼 가운데 왼쪽 −4에 붙였으나, 그것은 사용자가 옮기기 전 자리였고 네크로맨서가 두 창 사이에 가려져서 바꿈).
- 인벤토리 창에 틀을 붙이면 창이 커진다 (UI 좌표 184×152 → 204×172, 틀 띠 12 때문). 창 위 끝을 붙이기 전 자리에 두고 아래로 커지게 한다 (offset_top −78 → −68, offset_bottom 9 → 19). HUD 셋째 줄과 닿지 않게 (사용자 결정, 2026-11-17. ui-designer 비교판의 B를 고름).
- 창고·상자 창(`ui/storage_screen.tscn`)에 틀을 붙이면 창이 커진다 (UI 좌표 세로 224 → 244, 가로 +20). 위 끝을 붙이기 전 자리(y 68)에 두고 아래로 커지게 한다 (offset_top·bottom 0 → 10, grow_vertical 2 그대로, 아래 끝 312). 인벤토리 창과 같은 꼴이고, 두 창 위 끝은 1.5 차이로 나란하다 (사용자 결정, 2026-11-17. compare-variants 비교판에서 지금 / 위아래로 같이 / 위 끝 그대로 / 인벤토리 위 끝에 맞춤(11.5)을 거점 창고·지역 상자에서 견주고 3번을 고름. 비교판은 저장소에 남기지 않음).
- 수리 창(`ui/repair_screen.tscn`)에 틀을 붙이면 창이 커진다 (UI 좌표 158×112 → 178×132). 위 끝을 붙이기 전 자리(y 124)에 두고 아래로 커지게 한다 (offset_top·bottom 0 → 10, grow_vertical 2 그대로, 아래 끝 256). 창고·상자 창과 같은 꼴이다. 이유 줄이 뜰 때 창이 위아래로 같이 커지는 것(위 끝 약 9.5 올라감, 계산)은 그대로 둔다 (사용자 결정, 2026-11-17. compare-variants 비교판에서 지금 / 위아래로 같이 / 위 끝 그대로 / 인벤토리 위 끝에 맞춤(-44.5)을 거점 수리 화면에서 견주고 3번을 고름. 비교판은 저장소에 남기지 않음).
- 칸에 아이템 아이콘을 붙이려면 아이템 데이터(`ItemData`)에 `@export var icon: Texture2D` 칸을 두어 .tres마다 그림을 건다. 비면 지금의 임시 도형을 쓴다 (사용자 결정, 2026-11-17. 새 머리뼈는 .tres와 그림만 더하면 되게. 구현함 2026-11-17, 아래 5단계 결과 "칸 아이콘").
  - 아이콘은 아이템을 보이는 모든 칸에 보인다: 인벤토리·창고·상자 칸(`InventorySlot`), 핫바 칸(`HotbarSlot`), 수리 칸(`RepairSlot`), 끌 때 마우스를 따라다니는 그림까지 (사용자 결정, 2026-11-17. 선택 UI에서 추천안을 고름, 말로 준 이유 없음. 핫바는 틀을 아직 붙이지 않은 HUD라 아이콘만 먼저 바뀜).
  - 동굴 두꺼비 머리뼈(`data/skulls/cave_toad_skull.tres`)는 기준 세트에 아이콘이 없어 `icon`을 비우고 임시 도형 그대로 둔다. 두꺼비를 지역에 넣을 때 받는다 (사용자 결정, 2026-11-17).

## 보류

- OpenAI API 키로 받기: Codex CLI로 구독 한도 안에서 받기로 해서 쓰지 않는다. 다시 볼 조건: 구독 한도가 모자랄 만큼 많이 뽑게 될 때.
- 전투 장면 촬영 도구(`tools/shot_view_3d_combat.gd`)가 찍을 순간(멧돼지 예고·돌·탄이 한 화면)을 못 찾고 "900프레임 안에 … 함께 보이지 않음"으로 실패한다. 고해상도 UI 전부터 있던 문제다 (origin/main e037729에서도 같음). 그래서 3b에서 바꾼 저장(기본 창 그림, `--game_only`)은 이 도구에서 확인하지 못했다 (사용자 결정, 2026-11-16: 보류에 적고 나중에). 다시 볼 조건: 이 도구로 전투 장면을 찍어야 할 때.
- 정보 줄이 세 줄이면 창이 자라 칸이 움직이는 것: 인벤토리 칸에 마우스를 올려 정보 줄이 세 줄이 되면 인벤토리 창이 172 → 175로 위아래로 자라 칸이 1.5(1920에서 약 4.5px) 움직인다 (InfoLabel 최소 높이 48, `ui/inventory_screen.tscn`). 창고 창도 같다. 아이템 메뉴 setup을 고치다 찾았다 (사용자 결정, 2026-11-17: 나중에). 다시 볼 조건: 정하지 않음.
- 핫바 HUD에 창 틀을 붙일지: 5단계에서 정하지 않았다 (위 "정한 것"의 창 틀 다음 순서 줄). 핫바 칸은 아이콘만 바뀌었고 틀·칸 모양은 붙이기 전 그대로다 (사용자 결정, 2026-11-17: 보류에 적음). 다시 볼 조건: 정하지 않음.
- 창고·상자 창과 채집·탈출 게이지 겹침: 게이지 둘이 함께 뜨면(UI y≈302~348, x 260~380) 틀을 붙여 아래 끝이 312가 된 창고·상자 창과 x 324~380에서 겹친다. 틀을 붙이기 전(아래 끝 292)에는 겹치지 않았고, 드물게 일어난다 (5단계 결과의 창고·상자 창 틀·칸 줄. 사용자 결정, 2026-11-17: 보류에 적음). 다시 볼 조건: 정하지 않음.

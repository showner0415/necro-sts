# 창 틀 다시 만들기 (2026-11-18)

상태: 진행 중 (1단계) (2026-11-18)
브랜치: `ui-frame` (main `df3dcf1`에서 땀, 사용자 결정 2026-11-18. 합치는 때는 정하지 않음)

## 목표

고해상도 UI의 창 틀(`assets/ui_hd/window_frame.png`, 깎은 돌 띠)을 새로 그린다. 사용자가 "틀이 좀 맘에 안 들어, 그냥 스타일이 이상해. zero sievert 2 이거 검색해 봐. 이거랑 비슷한 스타일로 게임 만들 건데, 프레임만 이런 감성으로 다시 만들어 줘"라고 했다 (2026-11-17).
하지 않는 것: 아이콘·칸·버튼·아이템 메뉴 바꾸기 (어울림은 비교판에서 보고 나중에 정한다), 창 자리·크기 바꾸기, 그 게임의 UI 그림을 베끼거나 그 게임 스크린샷을 그림 요청에 넣기 (분위기만 우리 말로 적는다).

## 정한 것 (사용자, 2026-11-18)

- 창 틀을 다시 만든다. 지금 틀(깎은 돌 띠, 2026-11-17 확정)은 새 틀을 고르면 바꾼다 (사용자 결정, 2026-11-17. "틀이 맘에 안 들어, 스타일이 이상해").
- 방향은 "장식 없는 평면 판"이다: 어두운 판에 얇은 테두리, 장식이 거의 없는 실용적인 생존 장비 느낌 (사용자 결정, 2026-11-18. 선택 UI에서 "군용 금속판"·"두 방향 다 시안" 안도 있었음).
- 틀은 지금처럼 GPT 그림(Codex)으로 그린다 (사용자 결정, 2026-11-18. "둘 다 시안 내서 비교판(추천)"·"Godot 테마로만" 안도 있었음).
- 틀만 바꾼다. 칸·수리 버튼·아이템 메뉴의 색(갈색 계열 3e2731·733e39)과 어울리는지는 비교판에서 보고 나중에 정한다 (사용자 결정, 2026-11-18).
- 작업 브랜치는 새 브랜치 `ui-frame`이다 (사용자 결정, 2026-11-18).

## 문제와 위험

| # | 문제 | 내용 | 대응 |
|---|---|---|---|
| 1 | 요청문 틀의 고정 스타일 문장이 돌 틀용이다 | `docs/ui-style.md` "요청문 틀"과 `art_src/ui/style/frame.txt`는 "Low-poly … carved stone … dark cave"다. 평면 판과 맞지 않는다 | 틀 요청문만 새로 쓴다 (제안). 아이콘 요청문 틀은 그대로 둔다 |
| 2 | 줄여 그리면 얇은 선이 흐려진다 | 1920 기준 그림을 1/3로 줄여 그린다 (`ui/theme/scaled_frame_style_box.gd`). 1~2px 선은 1/3에서 사라지거나 흐려질 수 있다 | 1920 기준에서 테두리를 3px 이상으로 요청하고, 후보를 게임 화면(1280×720·창 최대화)에서 본다 (제안) |
| 3 | 창 크기가 바뀔 수 있다 | 지금 틀 띠 12, 창 안쪽 여백 14(확정). 띠 굵기를 바꾸면 네 창의 크기와 자리를 다시 봐야 한다 | 띠 12(1920에서 36px)와 여백 14는 그대로 두고, 그 띠 안에 얇은 테두리를 그린다 (제안) |
| 4 | 판 색과 칸·메뉴 갈색이 따로 놀 수 있다 | 칸·버튼·메뉴는 3e2731·733e39 갈색이다 | 비교판에서 보고 나중에 정한다 (정한 것) |

## 단계

### 1단계: 새 틀 후보 받기

상태: 진행 중 (후보 받음, 사용자가 고르기 전. 사용자가 "지금은 고를 시간이 없다, 다른 세션에서 평면 판 창 틀 후보 선택지를 달라고 하면 그때 다시 선택지를 주면 된다"고 함, 2026-11-18)

할 일:
- `ui-designer` "요청문"으로 평면 판 틀 요청문을 쓰고 Codex로 후보를 받는다. 받은 후보는 검사·다듬기만 하고 붙이지 않는다 (고르는 것은 사용자). (끝남, 2026-11-18)
- 후보를 한 장의 비교판으로 만든다. (끝남, 2026-11-18)

통과 기준:
- 스크립트로 재는 것: 후보마다 `tools/ui_gen/check_ui_image.gd` 결과가 있다 (충족)
- 사용자가 보는 것: 후보 비교판에서 게임 화면에 올려 볼 후보를 고른다 (아직)

사람이 정할 것 (사용자가 "평면 판 창 틀 후보 선택지"를 달라고 하면 이 셋을 선택 UI로 묻는다. 비교판을 먼저 열어 보여 준다):
- [ ] 게임 화면(거점 창고·인벤토리·아이템 메뉴)에 올려 볼 후보 2~3개 (여럿 고름. 지금 돌 틀과 함께 찍는다). 선택지: 2번 회색 / 4번 국방색 두 줄 / 6번 국방색 밝음 / 5번 국방색 어두움 (1·3번은 흠이 있어 Other로). ui-designer 제안은 2·4·6번.
- [ ] 띠가 창 안쪽 판(181425)보다 밝아 "조금 밝은 테 + 더 어두운 안쪽" 두 단으로 보이는 것: 게임 화면에서 보고 정하기 (추천, 한도를 덜 씀) / 지금 띠를 판 색에 가깝게(선만 보이게) 다시 받기 (6장, 약 15분).
- [ ] 모서리: 45도 깎음 그대로 (추천, 후보가 모두 이 꼴) / 네모로 다시 받기. 깎음은 ui-designer의 제안이었다.

결과:
- 후보 받기 (2026-11-18): ui-designer가 Codex로 6장을 받았다 (`적용: 모델 gpt-6.1-sol, effort medium`, frame_gray 3/3, frame_olive 3/3, 한 장에 56~76초). 함께 넣은 그림은 없다 (돌 틀을 넣으면 재질·색이 돌로 끌려갈까 봐). 요청문에 그 게임 이름·그림은 넣지 않았다.
  - 요청문: `art_src/ui/inbox/frame_flat/prompts/frame_gray.txt`·`frame_olive.txt`. 첫 줄 스타일 문장은 새로 썼다 ("Plain, practical game UI art for a dark survival game: flat matte plates with thin, crisp border lines, like old but clean, well-kept equipment…"). 띠 색 회색 #262a33·선 #6e7686 / 국방색 #2b2d22·선 #6c6b4c, 선은 띠 두께의 1/6, 모서리 45도 깎음, 안쪽은 투명 구멍. 요청문 틀(`docs/ui-style.md`)에는 넣지 않았다 (제안).
  - 비교판: `art_src/ui/inbox/frame_flat/compare/frame_flat_sheet.png` (1~6 후보, 7 지금 돌 틀. 칸마다 원본 / 1920 기준 창 612×516 / 1280×720 크기 창). 다듬은 판(1배, 띠 36px)은 `art_src/ui/inbox/frame_flat/prepared/<후보>_1x.png`. 이 폴더는 git 밖이라 받은 컴퓨터에만 있다.
  - 후보 (본 것, 9-slice 여백 제안 왼·위·오·아래):

    | 번호 | 후보 | 본 것 | 여백 |
    |---|---|---|---|
    | 1 | frame_gray_1 | 검사 버림(투명 배경 아님, 바깥에 흐린 그림자). 깎은 모서리 자리에 흐린 자국 | 38,38,38,38 |
    | 2 | frame_gray_2 | 회색 선이 가장 굵고(5~6px) 또렷, 모서리 깨끗 | 38,38,39,37 |
    | 3 | frame_gray_3 | 아래 띠만 얇음 (다른 변 36px, 아래 29px) | 38,38,38,31 |
    | 4 | frame_olive_1 | 선이 바깥·안쪽 두 줄(요청은 한 줄), 안쪽 선이 판 경계를 깔끔하게 끊음, 선이 가장 가늘다 | 38,38,38,38 |
    | 5 | frame_olive_2 | 모서리 깎음이 가장 크고 선이 가장 어둡다 | 38,38,38,38 |
    | 6 | frame_olive_3 | 국방색 셋 중 띠와 선이 가장 밝다 | 38,38,39,38 |

  - 여섯 모두 글자·무늬 없음, 변 두께가 ±1px로 일정, 1280×720 크기에서도 바깥 선이 끊기지 않는다. 띠(밝기 0.16~0.18)가 판 181425(약 0.08)보다 밝아 두 단으로 보이고, 국방색 띠와 보랏빛 검정 181425가 맞닿는 곳은 색 차이가 눈에 띈다 (Claude가 비교판을 열어 봄).
  - 2단계에 넘길 것: `art_src/ui/inbox/`에는 `.gdignore`가 있어 `res://`로 못 읽는다. setup에서 `Image.load_from_file()` → `ImageTexture.create_from_image()`로 읽어 공용 테마의 `CanvasTexture_frame.diffuse_texture`와 여백을 실행 중에만 바꾸거나, 비교용 임시 폴더에 복사해 임포트한다. TILE_FIT·draw_center=false·texture_scale 1/3·panel_inset 6·content_margin 14는 그대로. 볼 것: 두 단 차이, 칸·메뉴 갈색과의 어울림, 4번 안쪽 선이 칸 격자와 겹쳐 보이는지.
  - 기록: `docs/ui-style.md` "요청 기록"에 6줄 (판정 없음).

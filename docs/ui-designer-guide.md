# ui-designer 에이전트 사용법

GPT로 그린 그림으로 게임 UI를 만드는 에이전트다. 그림은 사용자가 ChatGPT에서 그리고, 에이전트는 요청문 쓰기·걸러 고르기·Godot에 붙이기·기록을 맡는다.
에이전트 지시문: `.claude/agents/ui-designer.md` / 스타일과 기록: `docs/ui-style.md`

## 한눈에 보기

```
[처음 한 번]  고해상도 UI 층 만들기 → 스타일 고르기 → 기준 세트 확정
[화면마다]    요청문 받기 → ChatGPT로 후보 그리기 → 폴더에 전부 넣기 → 붙이기 → 비교판 보고 판정
[가끔]        정리 (쌓인 판정으로 요청문 틀 고치기)
```

## 0. 시작하기 전에

1. **고해상도 UI 층.** `docs/plans/2026-11-14_hd_ui_layer_plan.md`의 1~4단계를 Claude Code로 먼저 끝낸다. 이게 없으면 GPT 그림이 640×360으로 줄어 뭉개진다. 그 전에는 에이전트가 "스타일" 할 일만 한다.
2. **ChatGPT 프로젝트 하나 만들기 (권장).** ChatGPT에 이 게임용 프로젝트를 만들고, 스타일이 정해지면 `docs/ui-style.md`의 고정 스타일 문장과 기준 세트 그림을 넣어 둔다. 원본은 저장소의 `docs/ui-style.md`다. ChatGPT 쪽은 사본이니, 틀이 바뀌면 같이 바꾼다.

## 1. 스타일 고르기 (처음 한 번)

Claude Code에 말한다:
> UI 스타일 시안 뽑아 줘

1. 에이전트가 서로 다른 스타일 3안과 안마다 요청문을 준다. 셋 다 같은 인벤토리 창을 그리게 되어 있어 나란히 견줄 수 있다.
2. 요청문을 ChatGPT에 하나씩 넣어 그린다.
3. 그림을 보고 하나를 고른다. 창 틀과 버튼을 그림으로 할지 Godot 테마(색 상자)로 할지도 같이 고른다. 추천은 테마다: 창 크기가 바뀌어도 깨지지 않고, 검수할 그림이 줄어든다.

## 2. 기준 세트 확정 (처음 한 번)

고르면 에이전트가 기준 세트 요청문과 규격(크기, 외곽선, 빛 방향, 게임에 보이는 크기)을 준다. 기준 세트는 이후 모든 그림의 잣대다.

1. 요청문대로 아이콘 4~6개, 버튼 한 벌, 칸 하나를 ChatGPT로 그린다.
2. 받은 그림을 `art_src/ui/inbox/style/`에 넣고 말한다:
   > 기준 세트 넣었어, 검사해 줘
3. 에이전트가 실제 게임 크기로 줄인 비교판을 준다. 작게 봐도 읽히고 서로 어울리면 확정한다.
4. 확정하면 `docs/ui-style.md`의 상태가 `정함`이 된다. 여기서부터 화면 작업이 된다.

## 3. 화면 하나 만들기 (화면마다)

**① 요청문 받기**
> 퀘스트 창 UI 만들어 줘

에이전트가 화면에 필요한 부품을 나누고, 부품마다 요청문·후보 수·함께 넣을 그림을 표로 준다. 넣을 폴더(`art_src/ui/inbox/<화면 id>/`)도 만들어 둔다.

**② ChatGPT로 후보 그리기**
- 요청문을 그대로 넣고, 표에 적힌 기준 그림을 함께 첨부한다.
- 부품마다 후보를 3~4장 받는다 (다시 그리기를 누르면 된다).
- 요청문의 말을 바꾸고 싶으면 바꾸지 말고 Claude Code에 말한다. 바뀐 말은 기록에 남아야 다음에 쓸 수 있다.

**③ 폴더에 전부 넣기**
- 고르지 말고 받은 것을 전부 넣는다. 고르는 건 에이전트가 한다.
- 파일 이름은 `<부품>_<후보 번호>.png` (예: icon_bone_1.png, icon_bone_2.png).

**④ 붙이기**
> 넣어 둔 그림 붙여 줘

에이전트가 하는 일:
1. 스크립트 검사: 크기, 투명 배경(흰 배경을 그려 넣은 것), 차지하는 면적, 기준 세트와의 색 차이, 버튼 상태 맞춤, 9-slice로 쓸 수 있는지. 확실히 틀린 것은 여기서 빠진다.
2. 남은 후보를 기준 세트와 견줘 부품마다 하나를 고른다.
3. 고른 것과 버린 것을 실제 크기로 기준 세트 옆에 놓은 비교판을 만든다.
4. 고른 것을 Godot UI에 붙이고 실제 해상도 스크린샷을 찍어 확인한다.
5. 버린 것은 지우지 않고 rejected 폴더에 이유와 함께 둔다.

**⑤ 비교판 보고 판정하기 (가장 중요)**
- 에이전트의 선택이 맞으면 "좋아"로 끝내도 된다.
- 다르면 번호와 **이유 한 줄**을 말한다:
  > 2번 살려, 테두리가 덜 화려해서 좋아
  > 고른 아이콘 4는 너무 밝아

이 한 줄이 다음 요청문을 좋게 만든다. 이유 없이 "이거 별로"라고만 하면 에이전트가 이유를 추측해야 하고, 추측한 이유로는 요청문 틀을 바꾸지 않는다.

## 4. 정리 (가끔)

붙이기 보고에 "정리할 때가 됐다"가 나오면 (쓴 그림이 5개 넘게 쌓였거나 같은 버림 이유가 반복될 때):
> 요청문 정리해 줘

에이전트가 기록에서 공통점을 모아 요청문 틀을 고칠 안을 낸다. 바뀌는 줄만 전후로 보여 준다. 받아들이면 틀의 판 번호가 오르고, 다음 요청부터 새 틀을 쓴다. 보고에 화면마다 버림 비율이 나오니, 틀을 고친 뒤 버리는 그림이 줄어드는지 보면 된다.

## 자주 생기는 일

| 상황 | 할 일 |
|---|---|
| 한 부품의 후보가 모두 버려졌다 | 에이전트가 고친 요청문을 준다. 그걸로 다시 그려 넣는다 |
| 버려진 그림이 아깝다 | "rejected의 <파일 이름> 살려, <이유>"라고 말한다 |
| 그림에 글자가 들어갔다 | 쓰지 않는다. 글자는 게임 글꼴로 넣는다. 요청문에 "글자 없음"이 있는지 본다 |
| 흰 배경이 그려져 나온다 | ChatGPT에 투명 배경 PNG로 다시 달라고 한다. 스크립트 검사가 거른다 |
| 스타일 자체를 바꾸고 싶다 | "UI 스타일 다시 정하자"라고 말한다. 시안부터 다시 하고, 이미 붙인 화면을 다시 그릴지 같이 정한다 |
| 버튼 자리·글자 크기만 바꾸고 싶다 | 에이전트 없이 Claude Code에 바로 말한다. 그림을 다시 그릴 일이 아니다 |

## 하지 않는 것

- GPT를 직접 부르지 않는다. 그림은 사용자가 ChatGPT에서 그린다 (API로 자동 받기는 보류).
- 그림의 픽셀을 손으로 고치지 않는다. 자르기·크기 맞추기·나누기만 스크립트로 한다.
- 스타일 문장·기준 세트·요청문 틀을 혼자 바꾸지 않는다. 안만 내고, 사용자가 정한다.
- 커밋하지 않는다. 결과를 보고 사용자가 정한다.

# ui-designer 에이전트 사용법

GPT로 그린 그림으로 게임 UI를 만드는 에이전트다. 에이전트가 Codex CLI로 ChatGPT 구독 한도 안에서 그림 후보를 뽑고, 걸러 고르고, Godot에 붙이고, 기록한다. 사용자는 비교판을 보고 판정한다.
Codex 스크립트: `tools/ui_gen/codex_image.sh`
에이전트 지시문: `.claude/agents/ui-designer.md` / 스타일과 기록: `docs/ui-style.md`

## 한눈에 보기

```
[처음 한 번]  고해상도 UI 층 만들기 → 스타일 고르기 → 기준 세트 확정
[화면마다]    "○○ 창 만들어 줘" → (에이전트가 요청문·Codex로 후보 뽑기·걸러내기·붙이기) → 비교판 보고 판정
[가끔]        정리 (쌓인 판정으로 요청문 틀 고치기)
```

## 0. 시작하기 전에

1. **고해상도 UI 층.** `docs/plans/2026-11-14_hd_ui_layer_plan.md`의 1~4단계를 Claude Code로 먼저 끝낸다. 이게 없으면 GPT 그림이 640×360으로 줄어 뭉개진다. 그 전에는 에이전트가 "스타일" 할 일만 한다.
2. **두 PC 모두 Codex CLI 준비.** Git Bash에서 `codex --version`이 나오고 `codex login`으로 ChatGPT 계정에 로그인되어 있어야 한다. 없으면 `npm install -g @openai/codex`로 설치하고 `codex login`을 한다 (로그인 확인: `codex login status`). Codex는 만든 그림을 홈 폴더의 .codex/generated_images/에 두고, 스크립트가 거기서 새 그림만 가져온다.
   - 처음 한 번 시험: `echo 'A small bone icon on a transparent background' > /tmp/p.txt && bash tools/ui_gen/codex_image.sh --prompt-file=/tmp/p.txt --out-dir=art_src/ui/inbox/test --name=test --count=1` → `결과: 1/1장`이 나오고 그 폴더에 test_1.png가 생기면 된다. 시험 폴더는 지운다.
   - 옵션 오류가 나면(버전마다 다르다) `CODEX_IMAGE_FLAGS` 환경 변수로 바꾼다 (스크립트 맨 위 주석).
   - **모델과 effort는 정해져 있다 (2026-11-15): 글 모델 GPT-6.1 Sol, effort medium.** 글 모델은 요청문을 읽고 그림 도구를 부르기만 한다. 그림을 그리는 모델은 Codex가 정하고 고를 수 없다. 스크립트가 이 값을 매번 넘기므로 각 PC의 Codex 설정과 상관없이 같게 돈다. 실행하면 `적용: 모델 …, effort …` 줄이 나온다. 시험 때 이 줄이 정한 값과 같은지 본다.
   - Codex가 없는 컴퓨터에서는 에이전트가 요청문만 주고 멈춘다. 그때는 아래 "직접 받기"대로 한다.
3. **구독 한도.** 그림 한 장마다 ChatGPT 구독 한도를 쓰고, 글 작업보다 빨리 닳는다. 에이전트는 한 번에 12장까지만 뽑고 보고에 받은 수를 적는다. Codex에서 `/status`로 남은 한도를 볼 수 있다.

## 1. 스타일 고르기 (처음 한 번)

Claude Code에 말한다:
> UI 스타일 시안 뽑아 줘

1. 에이전트가 서로 다른 스타일 3안을 만들고, Codex로 안마다 2장씩 뽑아 번호 붙은 비교판을 준다. 셋 다 같은 인벤토리 창이라 나란히 견줄 수 있다.
2. 비교판을 보고 하나를 고른다. 창 틀과 버튼을 그림으로 할지 Godot 테마(색 상자)로 할지도 같이 고른다. 추천은 테마다: 창 크기가 바뀌어도 깨지지 않고, 검수할 그림이 줄어든다.

## 2. 기준 세트 확정 (처음 한 번)

고르면 에이전트가 기준 세트 요청문과 규격(크기, 외곽선, 빛 방향, 게임에 보이는 크기)을 준다. 기준 세트는 이후 모든 그림의 잣대다.

1. 에이전트가 Codex로 기준 세트 후보를 뽑아 (아이콘 4~6개와, 그림으로 하기로 한 틀·버튼·칸. 지금은 창 틀만 그림이고 칸·버튼은 테마다) 검사하고, 실제 게임 크기로 줄인 비교판을 준다. 작게 봐도 읽히고 서로 어울리면 확정한다.
4. 확정하면 `docs/ui-style.md`의 상태가 `정함`이 된다. 여기서부터 화면 작업이 된다.

## 3. 화면 하나 만들기 (화면마다)

**① 맡기기**
> 퀘스트 창 UI 만들어 줘

후보 수를 바꾸려면 "부품마다 4장씩"처럼 덧붙인다 (기본 3장, 한 번에 12장까지).

**② 에이전트가 하는 일** (한 번에 몇 분~십여 분)
1. 화면에 필요한 부품을 나누고 요청문 틀로 요청문을 쓴다 (영어).
2. Codex로 부품마다 후보를 뽑는다. 기준 세트 그림을 함께 넣는다.
3. 스크립트 검사: 크기, 투명 배경(흰 배경을 그려 넣은 것), 차지하는 면적, 기준 세트와의 색 차이, 버튼 상태 맞춤, 9-slice로 쓸 수 있는지. 확실히 틀린 것은 여기서 빠진다.
4. 남은 후보를 기준 세트와 견줘 부품마다 하나를 고른다.
5. 고른 것과 버린 것을 실제 크기로 기준 세트 옆에 놓은 비교판을 만든다.
6. 고른 것을 Godot UI에 붙이고 실제 해상도 스크린샷을 찍어 확인한다.
7. 버린 것은 지우지 않고 rejected 폴더에 이유와 함께 둔다.

**③ 비교판 보고 판정하기 (가장 중요)**
- 에이전트의 선택이 맞으면 "좋아"로 끝내도 된다.
- 다르면 번호와 **이유 한 줄**을 말한다:
  > 2번 살려, 테두리가 덜 화려해서 좋아
  > 고른 아이콘 4는 너무 밝아

이 한 줄이 다음 요청문을 좋게 만든다. 이유 없이 "이거 별로"라고만 하면 에이전트가 이유를 추측해야 하고, 추측한 이유로는 요청문 틀을 바꾸지 않는다.

**직접 받기 (Codex가 없을 때)**
1. 에이전트가 준 요청문(영어)을 ChatGPT에 그대로 넣고, 표에 적힌 기준 그림을 함께 첨부한다. 부품마다 후보를 3~4장 받는다.
2. 고르지 말고 받은 것을 전부 `art_src/ui/inbox/<화면 id>/`에 `<부품>_<후보 번호>.png` 이름으로 넣는다 (예: icon_bone_1.png).
3. "넣어 둔 그림 붙여 줘"라고 하면 ② 의 3부터 한다.

요청문의 말을 바꾸고 싶으면 직접 고치지 말고 Claude Code에 말한다. 바뀐 말은 기록에 남아야 다음에 쓸 수 있다.

## 4. 정리 (가끔)

붙이기 보고에 "정리할 때가 됐다"가 나오면 (쓴 그림이 5개 넘게 쌓였거나 같은 버림 이유가 반복될 때):
> 요청문 정리해 줘

에이전트가 기록에서 공통점을 모아 요청문 틀을 고칠 안을 낸다. 바뀌는 줄만 전후로 보여 준다. 받아들이면 틀의 판 번호가 오르고, 다음 요청부터 새 틀을 쓴다. 보고에 화면마다 버림 비율이 나오니, 틀을 고친 뒤 버리는 그림이 줄어드는지 보면 된다.

## 자주 생기는 일

| 상황 | 할 일 |
|---|---|
| 한 부품의 후보가 모두 버려졌다 | 에이전트가 고친 요청문을 준다. "그 부품 다시 뽑아 줘"라고 하면 Codex로 다시 뽑는다 |
| Codex가 그림을 못 받았다 | 보고에 로그 끝 줄이 나온다. 한도가 찼으면 기다리거나 직접 받기로 한다. 옵션 오류면 `CODEX_IMAGE_FLAGS`를 바꾼다 |
| 그 모델을 쓸 수 없다는 오류 | 계정에 GPT-6.1 Sol이 없다는 뜻이다. Codex에서 `/model`로 쓸 수 있는 모델을 보고 다시 정한다. 당장은 `CODEX_IMAGE_MODEL=` 을 앞에 붙이면 그 PC의 Codex 설정 모델로 돈다 |
| "effort가 정한 값과 다르다" 경고 | Codex 관리자 설정이 덮어쓴 것이다. 그림은 그대로 받으니 써도 된다. 계속 나오면 Codex 버전·설정을 본다 |
| 버려진 그림이 아깝다 | "rejected의 <파일 이름> 살려, <이유>"라고 말한다 |
| 그림에 글자가 들어갔다 | 쓰지 않는다. 글자는 게임 글꼴로 넣는다. 요청문에 "글자 없음"이 있는지 본다 |
| 흰 배경이 그려져 나온다 | 스크립트 검사가 거른다. 계속 나오면 "요청문 정리해 줘"로 틀에 투명 배경 문장을 더 분명히 넣는다 |
| 스타일 자체를 바꾸고 싶다 | "UI 스타일 다시 정하자"라고 말한다. 시안부터 다시 하고, 이미 붙인 화면을 다시 그릴지 같이 정한다 |
| 버튼 자리·글자 크기만 바꾸고 싶다 | 에이전트 없이 Claude Code에 바로 말한다. 그림을 다시 그릴 일이 아니다 |

## 하지 않는 것

- OpenAI API 키를 쓰지 않는다. 그림은 Codex CLI로 구독 한도 안에서만 받는다. Codex를 코드 작업에 쓰지 않는다.
- Codex 폴더(홈의 .codex) 안의 로그인 정보를 읽지 않는다.
- 그림의 픽셀을 손으로 고치지 않는다. 자르기·크기 맞추기·나누기만 스크립트로 한다.
- 스타일 문장·기준 세트·요청문 틀을 혼자 바꾸지 않는다. 안만 내고, 사용자가 정한다.
- 커밋하지 않는다. 결과를 보고 사용자가 정한다.

# 아트 방향과 에셋 규칙

아래 확정 규칙은 이후 모든 에셋에 적용한다. 미정 항목과 제안은 사용자에게 물어서 확정한 뒤에만 적용한다.

## 기본 방향

| 항목 | 값 | 상태 |
|---|---|---|
| 시점 | 2.5D: 캐릭터는 2D 도트 그림, 맵은 3D. 게임 규칙은 2D 평면 그대로이고 화면만 3D로 그린다 | **확정** |
| 스타일 | 픽셀 아트 | **확정** |
| 기준 크기 | 32px (바닥 타일 32×32, 사람형 캐릭터 32×32) | **확정** |
| 팔레트 | Endesga 32 고정 (`assets/palette/endesga-32.hex`) | **확정** |
| 카메라 | 각도 고정, 비스듬한 위 (3/4 시점). 아래로 70도, 원근 화각 30도, 화면을 맵 기준 45도 돌림 | **확정** |
| 벽 높이 | 96px (타일 3칸) | **확정** |
| 내부 해상도 | 640×360, 정수 배율로 늘리기 | **확정** |

## 제작 도구

- 생성 스크립트로 PNG를 만든다.
  - Python + Pillow가 설치되어 있으면 `tools/asset_gen/*.py`
  - 없으면 Godot 스크립트(`Image` 클래스, `save_png`)로 `tools/asset_gen/*.gd`를 만들고 `bash tools/godot.sh --headless -s <스크립트>`로 실행
- 결과물을 다시 만들 수 있어야 한다. 조정은 파라미터를 바꿔 재생성하는 방식으로 한다.
- 팔레트 검사: `bash tools/godot.sh --headless --path . -s tools/check_palette.gd` (인자가 없으면 `assets/` 전체, `-- <파일이나 폴더>`로 대상 지정). 팔레트 밖의 색이 있으면 파일·색·위치를 출력하고 종료 코드 1로 끝난다.

## 제안 (사용자 확인 전)

- **언데드 에셋 재사용**: 몬스터마다 언데드 버전이 있으므로, 언데드는 원본 몬스터 에셋에 공통 변형(채도 낮추기, 뼈색 톤, 빛나는 눈 등)을 적용해 만드는 방식을 제안한다. 생성 스크립트에 "언데드 변형" 옵션을 두면 몬스터 하나를 추가할 때 언데드도 같이 나온다.

## 확정된 규칙

- 시점은 2.5D다 (2026-11-10). 캐릭터는 2D 도트 그림, 맵은 3D이고, 높이는 게임에 영향이 없다 (바닥은 평평하고 3D는 보이는 모습에만 쓴다). 이동·충돌·길찾기·시야 판정은 2D 평면 그대로다. 에셋은 생성 스크립트로 PNG를 만든다.
- **스타일**: 픽셀 아트.
- **카메라 각도**: 비스듬한 위에서 내려다보는 3/4 시점. 캐릭터와 몬스터는 얼굴과 몸 앞면이 보이게 그린다.
  - 카메라는 조준 방향으로 앞서 간다: 플레이어와 마우스 사이 거리의 30%, 최대 90px, 따라가는 빠르기 초당 6, 움직이지 않는 구역 반지름 32px (사용자 결정, 2026-11-10). 나중에 설정에서 세기를 0까지 줄일 수 있게 둔다.
  - 이동은 화면 기준이고 (W = 화면 위), 8방향 그림은 화면 방향 기준으로 고른다. 규칙 좌표는 맵 그대로다.
  - 몸 그림은 3D에서 카메라를 정면으로 보게 그린다 (사용자 결정, 2026-11-10. 원근에서 세운 그림이 화면 옆으로 갈수록 기울어 거슬렸다). 그림 1픽셀 = 화면 1픽셀이다.
- **앞벽 처리** (카메라 쪽 벽, 사용자 결정, 2026-11-10): 플레이어와 조준점 주변은 잘라낸다. 시야 안의 몸·물건·상자와 앞벽 뒤 바닥의 예고 표시(돌진 선, 돌 떨어질 원) 앞은 반투명하다. 탄과 돌은 앞벽을 반투명하게 하지 않는다. 전환은 깜빡이지 않게 서서히 한다.
  - 잘라내기 반경은 플레이어 64, 조준점 48 화면 픽셀이다 (사용자 결정, 2026-11-10: 플레이해 보고 일단 이대로. 개발 빌드의 `[` `]` `-` `=` 키로 바꿔 볼 수 있다).
- **카메라 기울기와 벽 높이** (사용자 결정, 2026-11-10): 처음 값 60도·32px에서 벽이 너무 낮아 벽을 3배(96px)로 올리고, 가리는 바닥이 늘지 않게 기울기를 70도로 했다. 측정: 앞벽 처리를 켠 상태에서 가린 바닥 화면 전체 5.2%, 좁은 길에 섰을 때 둘레 4칸 14.9%.
- **기준 크기**: 바닥 타일은 32×32, 사람형 캐릭터(네크로맨서, 전사 등)는 32×32 캔버스에 그린다.
- **픽셀 밀도 통일**: 모든 그림은 같은 픽셀 크기로 그린다. 크게 그려서 줄이거나 작게 그려서 늘리지 않는다.
- **게임 안의 확대·축소**: 스프라이트를 키워서 더 큰 몬스터로 쓰지 않는다. 피격, 소환, 사망처럼 잠깐 보이는 연출용 확대·축소는 허용한다.
- **캔버스 크기**: 몬스터의 몸 모양에 맞춰 다르게 한다. 작은 몬스터는 더 작게, 네발짐승은 가로로 길게, 큰 몬스터와 보스는 더 크게 한다. 강한 몬스터일수록 크게 보이게 한다. 종류별 크기는 아래 표를 따른다.
  - 예외: 크기 대신 속도로 강함을 보여주는 몬스터는 작게 둔다 (예: 박쥐는 2등급이지만 16×16).
  - 예외: 쥐는 작은 몬스터지만 32×32 캔버스다 (사용자 결정, 2026-11-08). 그림이 확정되어 있다 (`assets/ASSETS.md`). 다른 작은 몬스터(박쥐·슬라임 등)는 16×16 그대로다.
  - 사람형은 기본 32×32이지만, 특성이나 강함을 표현하기 위해 48×48도 허용한다.
  - 언데드는 원본 몬스터와 같은 캔버스 크기를 쓴다.
- **네임드 표시**: 네임드는 크기를 바꾸지 않고 테두리와 색으로 구별한다.
- **기준점과 정렬**: 스프라이트 기준점은 발밑(캔버스 아래쪽 가운데)에 둔다. 3D 화면에서 앞뒤는 발밑에 수직으로 세운 판의 깊이로 정한다 (뒤쪽 벽에 머리가 파묻히지 않고 앞쪽 벽에는 가린다). 2D 씬의 Y 정렬(`y_sort_enabled`)은 2D로 그릴 때(`--view_2d`)만 쓴다.
  - 예외: 외부 도구로 만든 그림처럼 발이 캔버스 맨 아래에 있지 않으면, 실제 발 위치를 기준점으로 둔다 (`Sprite2D`의 `offset`으로 맞춘다). 네크로맨서는 발이 y=28에 있어 offset이 (-16, -28)이다.
    - 네크로맨서 걷기 프레임(PixelLab)은 40×40 캔버스다. 캐릭터 크기는 정지 그림과 같고 사방에 투명 여백 4px이 붙어, 발이 y=32에 있다. 자르지 않고 그대로 쓰며 기준점은 (-20, -32)다 (사용자 결정, 2026-11-08). 캔버스 크기 규칙의 예외지만 픽셀 밀도는 같다.
    - 쥐는 발이 y≈25에 있어 모든 방향에 같은 offset (-16, -25)을 쓴다 (`rat.tres`의 `sprite_offset`). 방향마다 다르게 하면 방향이 바뀔 때 들썩여 보여서 하나로 둔다.
- **화면 설정** (`project.godot`):
  - 기본 텍스처 필터는 Nearest로 해서 픽셀이 흐려지지 않게 한다.
  - 내부 해상도 640×360, 늘리기 방식 `viewport`, 배율은 정수(`integer`)로 한다.
- **팔레트**: Endesga 32 (ENDESGA, 32색, https://lospec.com/palette-list/endesga-32). Resurrect 64에서 바꿨다 (2026-11-06).
  - 사용 조건: Lospec 팔레트 페이지에는 라이선스나 사용 조건이 적혀 있지 않다 (2026-11-06 확인). 출시 전에 ENDESGA에게 확인하고 크레딧에 표기한다.
  - 모든 에셋은 `assets/palette/`의 팔레트 색만 쓴다.
  - 생성 스크립트는 팔레트 파일에서 색을 읽는다. 스크립트에 색 값을 직접 적지 않는다.
  - AI 도구로 만든 그림은 넣기 전에 팔레트 색으로 맞춘다.
  - 팔레트 밖의 색을 쓰는지 `tools/check_palette.gd`로 검사한다.
  - 그림이 생기기 전까지 코드에서 그리는 임시 도형(몬스터·언데드·시체·아이템·바닥 표시 등)의 색도 팔레트에서 가져온다. 코드·씬·데이터에 적힌 색은 `tests/unit/test_palette_colors.gd`가 검사한다 (`bash tests/run_all.sh`에 포함).
- **가장 어두운 색(181425)은 외곽선 전용**이다. 게임 화면(바닥, 임시 도형, 바닥 표시)에는 외곽선 말고는 쓰지 않는다. 바닥에 쓰면 캐릭터 외곽선이 바닥에 묻힌다.
  - 예외: UI 창·칸 배경은 181425를 쓴다 (바닥 위에 뜨는 창이라 가장 어두운 배경이 글자를 읽기 쉽게 한다). 글자 외곽선은 외곽선이므로 그대로 쓴다.
  - 지금 바닥 색: 시험 지역 3e2731/262b44, 거점 193c3e/265c42 (임시 바닥 체크무늬).
  - 임시 벽 색 (`regions/placeholder_walls.gd`): 윗면 5a6988, 아래가 바닥인 칸의 앞면 띠 8b9bb4 (6px). 그림이 생기기 전까지 쓴다.
- **경고 색**: 빨간색(e43b44)은 되돌릴 수 없는 손해(예: 죽은 판정), 또는 그 직전의 위험 상태(예: 내구도 바 25% 이하)에만 쓴다.
  - 되돌릴 수 있는 결과의 경고(예: 메뉴의 "소환이 해제됩니다")는 핫바의 소환 중 테두리와 같은 노란색(feae34)으로 한다.
- **조준점 커서**: 9×9 십자, 가운데 3×3은 비운다. 밝은 색 흰색(ffffff)에 어두운 테두리(181425, 외곽선) 1px를 둘러 11×11이다. 생성 스크립트로 만든다 (`tools/asset_gen/aim_cursor.gd`).
  - 시스템 커서는 창의 실제 픽셀로 그려지므로, 창 배율(정수)마다 한 게임 픽셀을 배율만큼 키운 그림을 따로 만든다 (지금 1~6배).

### 몬스터 캔버스 크기

픽셀 밀도는 모두 같으므로 캔버스가 크면 화면에서도 그만큼 크게 보인다.

| 분류 | 예 | 캔버스 (가로×세로) | 비고 |
|---|---|---|---|
| 작은 몬스터 | 박쥐, 슬라임 | 16×16 | 초반 사냥감 |
| 쥐 (예외) | 쥐 | 32×32 | 사용자 결정으로 쥐만 32×32 (2026-11-08). 작은 몬스터 칸의 예외 |
| 사람형 | 네크로맨서, 전사, 해골병사 | 32×32 | 기준 크기. 특성·강함 표현용으로 48×48 허용 |
| 네발짐승 | 늑대, 멧돼지 | 48×32 | 가로로 긴 몸 |
| 큰 사람형·중형 | 오우거, 트롤 | 48×48 | |
| 대형 | 거대 거미, 곰, 골렘 | 64×64 | |
| 보스 | 지역 보스 | 96×96 ~ 128×128 | 보스마다 지정 |

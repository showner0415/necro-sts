# 맵 만들기

메인 대화가 맡긴 맵 하나를 구상 → 그리기 → 변환 → 검사 → 보고까지 한다.
사용자는 긴 설명 없이 맡기고 싶어 한다. 그래서 빈 곳은 스스로 정하되, 스스로 정한 것은 모두 **제안**이다.
맵의 느낌은 걸어 봐야 안다. 그래서 두 번 멈춘다: 굴 구성을 글로 짠 뒤(구상), 색 칸 맵을 만든 뒤(그레이박스). 한 번 부를 때 한 곳까지만 간다.

## 지킬 것

- 사용자에게 직접 묻지 않는다 (선택 UI를 쓸 수 없다). 정할 수 없는 것은 그럴듯한 쪽으로 하고 "사용자에게 물을 것"에 적는다. 다른 에이전트를 부르지 않는다.
- 사용자의 말과 내 생각을 섞지 않는다. "사용자 설명"과 문서의 "사용자 결정"만 사용자의 것이다. 나머지는 어느 문서에도 **확정**으로 적지 않는다 (CLAUDE.md).
- **실제 맵은 건드리지 않는다.** 기존 맵을 고치는 일도 초안 이름(`<맵>_draft`)의 새 파일로 만든다. 고치지 않는 것: 기존 배치 PNG(`art_src/maps/`), 기존 지역 씬과 윤곽 파일(`regions/`), 거점(`regions/base.tscn`), 시험 지역, 기존 지역 데이터.
- 변환·검사 도구(`tools/map_from_png.gd`, `tools/map_png/`의 기존 파일)와 색 규칙은 고치지 않는다. 도구가 못 하는 것이 필요하면 멈추고 물을 것에 적는다.
- 몬스터는 이미 데이터와 맵 색이 있는 것만 놓는다 (`docs/maps/map_png_rules.md`의 물건 표). 새 몬스터가 어울리는 자리는 비워 두거나 가까운 기존 몬스터를 놓고, 물을 것에 "이 자리에 어떤 몬스터"를 적는다 (만드는 일은 monster-designer 에이전트).
- 거점 출구 잇기, 퀘스트, 상자 내용물, 몬스터 재등장 같은 미정 항목은 정하지 않는다.
- 커밋, push, 브랜치 만들기, 되돌리기는 하지 않는다. 만든 것은 작업 트리에 둔다.
- 코드는 CLAUDE.md대로 쓴다 (타입 명시, Godot 4 문법, 숫자는 맨 위 상수). Godot는 `bash tools/godot.sh`로만 돌린다. GODOT_PATH 오류로 돌지 않으면 바로 멈추고 그 오류를 돌려준다.
- 오래 걸리는 명령(윤곽·지형 굽기 약 3분, 길목 재기 약 2분 30초, `bash tests/run_all.sh`)은 Bash 도구의 시간 제한을 600000(10분)으로 늘려 돌린다.
- 돌리지 않은 것을 돌렸다고 쓰지 않는다. 저장한 그림은 Read로 열어 보고, 본 것만 적는다.

## 1. 요청 읽기와 준비

맡긴 말에 아래 블록이 있다. 빠진 줄은 "맡김"으로 본다.

```
## 맵 요청
날짜: <YYYY-MM-DD>
종류: <새 지역 / 기존 맵 고치기 (<맵 이름>)>
사용자 설명: <사용자의 말 그대로. 없으면 "없음 (알아서 구상)">
쓸 몬스터·난이도: <예: "박쥐 위주, 얕은 굴보다 어렵게". 없으면 "맡김">
크기·걷는 시간: <예: "얕은 굴 절반", "끝까지 3분". 없으면 "맡김">
멈출 곳: <구상 (기본) / 그레이박스>
승인한 구상: <사용자가 승인한 구상 문서의 경로와 고른 안, 고쳐 달라고 한 말. 없으면 "없음">
정한 것: <이 맵에 대해 사용자가 이미 정한 것. 없으면 "없음">
```

- "멈출 곳"이 그레이박스인데 "승인한 구상"이 없으면, 사용자가 구상 없이 끝까지 맡긴 것이다. 구상(2)을 스스로 하고 이어서 그린다.
- "승인한 구상"이 있으면 그 문서를 읽고 3부터 한다. 구상을 다시 짜지 않는다.

읽는다.
- `docs/maps/shallow_cave_design.md`: 1(사용자가 정한 방향), 2(배치 원칙), 4(크기), 5(일부러 넣지 않은 것), 6(아직 정하지 않은 것)은 모든 맵에 닿는다. 기존 맵을 고치면 그 맵에 닿는 뒤쪽 절도 읽는다 (굴 이름과 역할, 고친 내력).
- `docs/maps/map_png_rules.md` 전체 (색, 통로 모양, 굴과 통로의 비율, 바위, 변환).
- `.claude/skills/map-edit/SKILL.md` (도구와 명령), 쓸 도구의 맨 위 주석.
- `docs/game-design.md`의 "몬스터 종류와 등급"과 몬스터마다의 절, "거점과 탈출", "지역과 퀘스트", "지역 상자", "미정 항목".
- `git status --short`를 적어 둔다.

## 2. 구상

1. **목적을 한두 줄로 적는다.** 이 맵에서 플레이어가 겪을 것. 설명이 있으면 그 말에서 벗어나지 않는다. 없으면 지금 게임에 비어 있는 것에서 찾는다 (예: 아직 무대가 없는 몬스터, 얕은 굴이 요구하지 않는 움직임, 설계 문서가 다음 이야기로 가리키는 곳).
2. **굴 구성을 짠다.**
   - 굴마다: 이름과 역할, 등급(바닥 색), 크기(가로×세로 칸), 몬스터와 수, 상자, 입구 수, 바위.
   - 연결마다: 어느 굴과 어느 굴, 통로 길이와 폭, 길목인지. 고리·갈림길·막다른 굴이 어디인지.
   - 도착 지점 하나, 탈출 지점들.
   - 구간별 걷는 시간 목표 (걷기 속도는 설계 문서의 값).
3. **원칙과 맞춰 본다.** 맵 원칙 문서의 1·2·5의 항목마다 이 구성이 어떻게 지키는지 한 줄씩 적는다. 어긋나는 곳은 숨기지 않고 적는다.
4. 설명이 없거나 구성이 크게 갈릴 수 있으면 안을 두 개 낸다 (예: 고리형과 갈래형). 다른 점과 추천을 적는다.
5. **글자 약도를 그린다.** 굴은 이름과 등급을 적은 상자, 통로는 선, 길목은 `=`로 표시한다. 사용자가 한눈에 구조를 본다.
6. 구상을 문서로 남긴다.
   - 새 지역: `docs/maps/<id>_design.md`를 새로 만든다. 첫머리에 `상태: 제안 (사용자 확인 전, <날짜>)`와 사용자 설명을 그대로 적는다.
   - 기존 맵 고치기: `docs/maps/<맵>_draft_design.md`를 새로 만든다 (그 맵의 설계 문서는 고치지 않는다). 무엇을 왜 바꾸는지, 바뀌는 굴·연결만 적는다.
7. "멈출 곳"이 구상이면 여기서 멈추고 8의 꼴에서 "구상"과 "사용자에게 물을 것"을 채워 돌려준다.

## 3. 이름과 파일

- 새 지역의 id는 영문 소문자와 밑줄이다 (예: bat_hollow). 기존 맵을 고치는 초안은 `<맵>_draft`다. 아래 `<이름>`은 그 이름이다.
- 만드는 파일 (모두 새 파일):
  - 그리는 스크립트 `tools/map_png/draw_<이름>.gd`
  - 배치 PNG `art_src/maps/<이름>.png`
  - 지역 데이터 `data/regions/<이름>.tres` (`data/regions/shallow_cave.tres`를 본으로. 변환보다 먼저 만든다)
  - 지역 씬 `regions/<이름>.tscn`과 윤곽 파일 (도구가 만든다. 구운 지형은 저장소에 올리지 않는 파일이다)
- 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 멈춘다 (지난 초안이 남아 있다는 뜻이다. 물을 것에 적는다).

## 4. 그리기

- PNG는 손으로 찍지 않고 스크립트로 그린다. 값만 바꿔 다시 뽑을 수 있어야 한다 (CLAUDE.md "에셋").
- 그리는 공용 도구는 tools/map_png/ 아래 map_painter.gd다. **없으면 먼저 만든다** (class_name MapPainter, 노드에 의존하지 않는 RefCounted, `tools/map_png/map_layout.gd`의 색을 그대로 쓴다). 있으면 그것을 쓰고, 모자란 기능만 더한다.
  - 필요한 것: 고정 씨앗으로 울퉁불퉁한 굴 덩어리 칠하기, 꺾이는 점들을 잇고 구간마다 폭이 다른 통로 칠하기, 굴 안 바위 놓기, 물건 놓기(붙은 박쥐 = 한 무리), 테두리를 벽으로 두르기, 기존 PNG를 읽어 한 구역만 고치기.
  - 단위 테스트를 tests/unit/ 아래 test_map_painter.gd로 둔다 (같은 씨앗이면 같은 그림, 통로 폭, 테두리).
- `tools/map_png/draw_<이름>.gd`는 맨 위에 구상의 값(굴마다 가운데·크기·등급·씨앗, 통로마다 꺾이는 점과 폭, 바위, 물건)을 상수로 두고 MapPainter로 그려 PNG를 저장한다. `tools/map_png/add_spawns_2x.gd`처럼 맨 위 `##` 주석에 무엇을 그리는지와 실행 명령을 적는다.
  - 기존 맵 고치기는 원본 PNG를 읽어 초안 PNG로 저장하면서 바꿀 구역만 고친다. 원본에 쓰지 않는다.
- 그릴 때 `docs/maps/map_png_rules.md`의 규칙을 처음부터 지킨다: 길목·통로 최소 2칸, 통로마다 한 번은 꺾기, 곧은 구간 길이, 폭 바꾸기, 굴이 바닥의 대부분, 대칭 피하기, 바위 규칙, 멧돼지 굴의 곧은 길, 굴은 한 화면에 다 안 보이게.

## 5. 변환과 굽기

1. `bash tools/godot.sh --headless --path . -s tools/map_png/draw_<이름>.gd` 뒤 `bash tools/godot.sh --headless --path . --import`
2. `bash tools/godot.sh --headless --path . -s tools/map_from_png.gd -- --in=res://art_src/maps/<이름>.png --out=res://regions/<이름>.tscn --region=res://data/regions/<이름>.tres --name=<루트 노드 이름>`
   - 문제(모르는 색, 2칸보다 좁은 바닥, 가는 바위 등)가 나오면 그 칸을 보고 그리는 스크립트를 고친다. PNG를 직접 고치지 않는다.
   - 출력된 굴 목록(입구 수, 이어진 굴, 안의 물건)을 구상과 견준다. 기존 맵 고치기면 바꾸려던 곳 말고는 원본과 같아야 한다 (원본의 목록: 초안을 그리기 전에 원본 PNG를 같은 `--out`으로 한 번 변환해 적어 둔다).
3. `bash tools/godot.sh --headless --path . -s tools/map_png/make_cave_outline.gd -- --scene=res://regions/<이름>.tscn --in=res://art_src/maps/<이름>.png` (약 3분). 그다음 2를 한 번 더 돌린다 (씬이 윤곽을 쓰게).

## 6. 검사하고 고치기

- 바닥 통계: `bash tools/godot.sh --headless --path . -s tools/map_png/map_stats.gd -- --in=res://art_src/maps/<이름>.png` → 굴 비율, 통로마다 가장 넓은 곳·길목 칸 수를 규칙과 견준다.
- 길목 폭: `bash tools/godot.sh --headless --path . -s tools/map_png/measure_chokes.gd -- --scene=res://regions/<이름>.tscn --in=res://art_src/maps/<이름>.png --outline=res://regions/<이름>_outline.res` → 모든 몸이 모든 길목을 지나가야 한다.
- 걷는 시간: 구간마다 칸 최단 길이 × 타일 크기 ÷ 걷기 속도로 어림해 목표와 견준다 (그리는 스크립트가 `MapLayout`으로 계산해 출력하게 한다). 실제로 걸어 재는 도구(`tests/balance/run_choke_walk.gd`, `tests/balance/run_stuck_walk.gd`, 얕은 굴 시나리오)는 얕은 굴 씬에 묶여 있어 다른 맵에는 못 쓴다. 보고에 "어림값"이라고 적는다.
- 얕은 굴의 초안이면 봇으로 지나가기도 잰다: `bash tools/godot.sh --headless --fixed-fps 60 --path . -s tests/balance/run_map_route.gd -- --scene=res://regions/<이름>.tscn --png=res://art_src/maps/<이름>.png --skills=normal --runs=3` (굴 역할을 바꾼 초안이면 길을 못 찾을 수 있다. 그러면 그렇게 적는다). 읽는 법은 `balance-measure` 스킬.
- 맵 전체 그림: `bash tools/godot.sh --path . -s tools/screenshot.gd -- --seconds=1 --view_2d --scene=res://regions/<이름>.tscn --setup=res://tools/screenshot_setups/map_overview.gd --out=<scratchpad 경로>/<이름>_overview.png` (창이 뜬다). Read로 열어 구상의 약도와 견준다: 굴 수와 자리, 연결, 대칭으로 보이지 않는지, 점을 관으로 이은 것처럼 보이지 않는지.
- 3D 화면 한 장: 도착 지점에서 `--scene=res://regions/<이름>.tscn`만 주고 찍어, 지형이 구운 모양으로 나오는지 본다 (칸 지형이면 굽기가 안 된 것이다).
- 어긋난 것은 그리는 스크립트의 값을 고치고 4~6을 다시 한다. 세 번 고쳐도 안 되면 멈추고 무엇이 안 되는지 적는다.
- 끝으로 `bash tests/run_all.sh` → `전체 결과: 통과`. 기존 테스트를 고쳐서 통과시키지 않는다. `git status --short`를 처음과 견주어 새 파일만 생겼는지 본다 (기존 파일이 바뀌었으면 잘못된 것이다).

## 7. 문서

- 구상 문서(2의 6)에 "그레이박스 결과" 절을 더한다: 그린 날짜, 실제 굴 목록, 검사 숫자, 구상과 달라진 곳과 까닭. 상태는 그대로 제안이다.
- 다른 문서(설계 문서, 색 규칙, CLAUDE.md, 스킬)는 고치지 않는다.

## 8. 돌려줄 것

아래 꼴 그대로 한국어로 짧게 쓴다. 하지 않은 절은 "하지 않음"과 까닭을 적는다.

```
## 맵

- 어디까지 했나: <구상 / 그레이박스>

## 구상
- 문서: <경로>
- 안 <번호> (<추천 / 승인받음>): 굴 <N>개, 길목 <N>곳, 끝까지 걷는 시간 약 <초>. <한 줄 특징>
- 약도:
```

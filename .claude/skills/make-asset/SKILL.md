# 에셋 제작 절차

사용자가 에셋을 요청하거나, 구현 중인 기능에 아직 없는 에셋이 필요해지면 이 절차를 따른다.
임시 도형으로 충분한 단계라면 먼저 "임시 도형으로 갈지, 지금 에셋을 만들지" 묻는다.

## 1. 아트 방향 확인

`docs/art-direction.md`를 읽는다.
- 이번 에셋에 필요한 기본 방향(시점, 스타일, 기준 크기, 팔레트)이 **미정**이면, 에셋 사양보다 먼저 그것부터 묻는다. 한 번에 최대 4개 질문, 각 질문에 추천안을 첫 번째 선택지로 둔다.
- 답을 받으면 `decide` 스킬로 `docs/art-direction.md`에 기록한다.

## 2. 사양 묻기

만들기 전에 이번 에셋의 사양을 묻는다. 이미 대화나 문서에 답이 있는 항목은 묻지 않는다.
- 무엇에 쓰이는지 (어떤 몬스터·아이템·UI인지)
- 크기와 방향 (정면/위에서 본 모습, 몇 방향이 필요한지)
- 애니메이션 필요 여부 (정지 / 걷기 / 공격 / 사망)
- 색과 특징 (이 에셋만의 구별 포인트)
- 몬스터라면 언데드 버전도 같이 만들지

선택지로 물을 수 있으면 선택지로 묻고, 추천안을 함께 제시한다.

## 3. 만들기

`docs/art-direction.md`의 "제작 도구"를 따른다.
- `tools/asset_gen/`에 생성 스크립트를 만든다. 조정할 만한 값(크기, 색, 비율, 눈 위치 등)은 스크립트 맨 위에 상수로 모아 둔다. 결과 PNG는 `assets/` 아래 해당 분류 폴더에 저장한다.
- 만든 뒤 `bash tools/godot.sh --headless --path . --import`로 임포트한다.
- 이미 있는 에셋을 다시 만들 때는 `assets/ASSETS.md`의 그 에셋 줄에 적힌 원본·생성 스크립트·명령·확인 스크린샷을 따른다 (예: 네크로맨서 애니메이션은 PixelLab ZIP에서 `tools/asset_gen/necromancer_anim.gd`로 꺼낸다).

## 4. 미리보기와 확인

- 결과 PNG를 직접 열어 확인한다. 의도와 다르게 나왔으면 사용자에게 보여주기 전에 먼저 고친다.
- 사용자에게 파일 경로와 함께 무엇을 만들었는지 한두 줄로 알린다.
- 조정할 수 있는 값이 무엇인지 알려준다. 예: "몸통 색, 눈 크기, 팔 길이를 바꿀 수 있습니다."

## 5. 조정

- 사용자의 피드백은 생성 파라미터를 바꿔서 반영한다. 결과 파일을 손으로 고치지 않는다.
- 여러 안을 비교하고 싶어 하면 파라미터만 다른 버전을 2~3개 만들어 나란히 보여준다.

## 6. 기록

`assets/ASSETS.md`에 한 줄을 추가하거나 갱신한다: 이름, 결과물 경로, 생성 스크립트·원본, 주요 파라미터, 상태.
- 새로 만든 에셋은 `검토 중`.
- 사용자가 좋다고 하면 `확정`으로 바꿀지 묻는다.
- `확정` 에셋은 사용자에게 묻지 않고 덮어쓰지 않는다.

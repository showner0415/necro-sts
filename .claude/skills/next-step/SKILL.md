# 단계 마무리와 다음 단계

한 단계가 끝날 때마다 이 절차를 밟는다.
예전에는 사용자가 보고를 웹 Claude에 붙여 넣어 다음 프롬프트를 받고, 그 프롬프트를 다시 여기에 붙여 넣었다. 단계마다 두 번 복사하고 앱을 바꿨고, 웹 Claude는 붙여 넣은 글만 봤다.
이제는 `step-review` 에이전트(`.claude/agents/step-review.md`)가 저장소를 직접 보고 검토와 다음 단계 초안을 쓴다. 사용자는 초안을 보고 "진행"하거나 고친다.

- 단계: 계획 문서의 한 단계, 또는 사용자가 한 번에 맡긴 일 하나.
- 건너뛰는 때: 문서·설정 몇 줄만 고쳤고 사용자가 그 한 곳을 짚었을 때, 설계 의논이나 질문에 답했을 때. CLAUDE.md 꼴로 보고만 하고, 끝에 "다음 단계 초안이 필요하면 /next-step"이라고 한 줄 적는다.
- 검토는 한 단계에 한 번 맡긴다. 고친 것이 크면 한 번 더 맡긴다 (4).

## 부르는 법

- 단계가 끝나면 사용자가 부르지 않아도 이 절차를 밟는다 (CLAUDE.md).
- `/next-step`: 방금 끝낸 단계. `/next-step <시작>..<끝>`: 그 커밋 범위를 한 단계로 본다 (지난 단계를 다시 볼 때). `/next-step 웹 요약`: 맨 아래 "웹에 붙일 요약"만 만든다.

## 1. 검증

CLAUDE.md "검증"대로 바뀐 것에 맞는 확인을 돌린다. 명령과 출력의 마지막 몇 줄을 보고에 그대로 옮긴다.
- 게임 코드·데이터·씬: `bash tests/run_all.sh` (마지막 줄 `전체 결과: 통과`)
- `view_3d/`나 게임 그리기: `bash tests/run_view_3d.sh`도 (창이 번갈아 뜬다, 약 3분)
- 화면에 보이는 것: 스크린샷을 찍고 PNG를 열어 본 것을 적는다 (`view-check` 스킬)
- 맵: `map-edit` 스킬의 5
- CLAUDE.md·스킬·에이전트·시나리오 주석만: `bash tests/check_rules.sh`

실패하면 고치고 다시 돌린다. 못 고쳤으면 실패를 그대로 보고에 적고 검토를 맡긴다.

## 2. 보고 쓰기

CLAUDE.md의 꼴(바꾼 것 (파일 단위), 실행해서 확인하는 방법, 에디터에서 사용자가 할 일)에 아래를 더한다. 이 보고를 검토에 넘기고 사용자에게도 보여 준다.
- 검증: 실행한 명령과 출력 일부, 스크린샷 경로와 그림에서 본 것
- 새 시스템이면 동작 방식 몇 줄
- 하지 않은 것, 남은 것, 알고 있는 문제, 사용자가 눈으로 볼 것

## 3. 검토 맡기기

Agent 도구로 `step-review`에 맡긴다. 프롬프트에 아래 블록을 채워 넣는다. 에이전트는 이 대화를 보지 못하므로 필요한 것을 모두 넣는다. 보고를 줄이거나 실패를 빼지 않는다.

```
## 검토 요청
날짜: <YYYY-MM-DD>
범위: <`<시작>..<끝>` 커밋 범위 / 작업 트리 (커밋 전) / `<시작>..HEAD`와 작업 트리>
계획 문서: <docs/plans/<파일>의 <N>단계 / 없음 / 모름>
다음에 하려던 것: <사용자가 말한 다음 할 일 (사용자의 말 그대로) / 계획 문서의 다음 단계 / 모름>

### 사용자 요청 (이번 단계, 사용자의 말 그대로)
<요청 전체. 여러 메시지면 모두. 승인한 초안으로 시작한 단계면 그 초안과 사용자가 고친 곳>

### 이번 단계에서 정한 것
결정: <사용자의 말 그대로>
출처: <선택 UI의 질문과 고른 답 / 대화 / 붙여 넣은 글 / 비교판>
날짜: <YYYY-MM-DD>
기록한 곳: <파일:줄 / 기록 전>
(결정마다 네 줄. 없으면 "없음")

### 단계 보고
<2의 보고 전체>
```

- 범위: 이번 단계의 첫 커밋 바로 앞부터 끝까지다 (`git log --oneline`으로 찾는다). 커밋하지 않았으면 "작업 트리".
- 계획 문서: 이번 단계를 시작할 때 쓴 계획이다. 대화에 나왔으면 그것이다. 아니면 `docs/plans/`에서 찾는다. `_template.md`는 틀이라 계획이 아니다. 이름이 `<날짜>_<주제>_plan.md` 꼴인 파일 중 맨 위 "상태:" 줄이 끝남이 아니고 이번 일을 다루는 것이다 (`grep -m1 '^상태' docs/plans/*_plan.md`). 하나로 못 정하면 "모름".
- 다음에 하려던 것: 사용자가 이번 요청과 함께 말한 다음 일이 있으면 그 말 그대로 쓴다. 계획이 있으면 "계획 문서의 다음 단계". 모르면 "모름"이라고 쓰고 지어내지 않는다.
- 정한 것은 decide 스킬의 세 줄에 "기록한 곳"을 더한 것이다.
- `step-review`를 찾지 못하면 대신 검토하지 않는다. 보고만 하고, Claude Code를 다시 시작한 뒤 /next-step을 다시 부르라고 알린다.

## 4. 검토를 받은 뒤

에이전트는 꼴이 정해진 검토(검토한 것, 검토 결과, 통과 기준, 사용자에게 물을 것, 다음 단계 프롬프트 초안)를 돌려준다.
- **꼭 고칠 것** 중 "범위: 안"은 고친다. 고친 뒤 닿는 확인을 1대로 다시 돌리고, 명령과 결과를 보고에 더한다.
  - 고치는 데 사용자의 결정이 필요하면(근거 없는 확정 등) 고치지 않고 물을 것으로 돌린다. 미정을 정하지 않는다.
  - "범위: 밖"은 고치지 않는다. 남은 것으로 보여 주고, 다음 단계 초안에 들어 있는지 본다.
- **확인 필요** 중 파일을 읽거나 명령 하나로 바로 볼 수 있는 것은 확인하고 결과를 적는다. 사용자가 정할 것은 물을 것으로 둔다.
- 검토가 틀렸다고 보면(파일을 잘못 읽음 등) 따르지 않고, 근거와 함께 "검토와 다름"으로 적는다. 말없이 빼지 않는다.
- 고친 것이 크면(새 파일, 규칙·동작 변경) 고친 범위만 같은 꼴로 한 번 더 맡긴다. 그 뒤에는 더 맡기지 않는다.
- 검토가 중간에 끊겼거나(최대 횟수) 꼴이 틀리면 받은 만큼만 쓰고 그렇다고 알린다.

## 5. 사용자에게 보여 주기

이 차례로 보여 준다.
1. 보고 (2에 4에서 고친 것을 더해서)
2. 검토 요약: 고친 것, 남은 것(꼭 고칠 것(범위 밖)·확인 필요·참고를 한 줄씩), 통과 기준 판정
3. 물을 것: 선택 UI로 묻는다 (CLAUDE.md). 검토의 "사용자에게 물을 것"을 중요한 것부터 4개씩 묶는다. 기능이 끝나고 테스트가 통과했으면 커밋하고 push할지도 묻는다 (CLAUDE.md "작업이 끝나면").
   - 화면 모양을 고르는 질문은 먼저 비교판을 만들지 묻는다. 만들기로 하면 검토가 적어 준 것을 `compare-variants`에 맡기고, 비교판을 보여 준 뒤 고르게 한다 (CLAUDE.md).
   - 사용자가 고른 결정은 검토가 적어 준 세 줄에 답을 채워 `decide` 스킬로 기록한다.
   - 답이 초안을 바꾸면 초안을 고친다. "나중에"거나 답이 없으면 초안의 "시작 전에 물을 것"에 남긴다.
   - "다음에 할 일"에서 초안과 다른 일을 고르면 검토를 다시 맡기지 않고, 같은 꼴(`.claude/agents/step-review.md`의 7)로 초안을 새로 쓴다. 명령과 파일은 저장소에서 찾아 쓴다.
4. 다음 단계 초안: 통째로 코드 블록에 넣는다 (복사해서 고치기 쉽게).

## 6. 계획 문서 진행 기록

계획 문서가 있으면 진행을 적는다. 결정은 decide가 적었으니 여기서는 진행만 적는다.
- 틀(`docs/plans/_template.md`)로 만든 계획: 그 단계의 "상태"를 `끝남 (YYYY-MM-DD)`로, "결과"에 넣은 것·잰 값·스크린샷 경로를 적고, 맨 위 "상태"를 다음 단계로 고친다. "진행 기록" 표에 한 줄(날짜 · 단계 · 한 줄 · 커밋)을 더한다. 커밋 칸은 짧은 해시이고, 아직 커밋하지 않았으면 `-`로 두었다가 다음에 이 표를 고칠 때 채운다.
- 틀 전에 만든 계획: 그 문서에 이미 있는 꼴(단계 아래 "넣은 것 (YYYY-MM-DD)" 줄, 맨 위 상태 줄)을 따른다.
- 사용자가 초안을 고쳐 다음 단계의 범위가 바뀌면 계획의 그 단계(할 일·통과 기준)도 고친다.
- 단계가 셋 이상인 새 일인데 계획이 없으면, 틀을 복사해 계획부터 만들자고 초안에 적는다.

## 7. 멈추기

- 사용자가 커밋하라고 했으면 6까지 마친 뒤 커밋한다 (decide 기록과 계획 문서도 같이). push도 하라고 한 것만 한다 (CLAUDE.md).
- 초안 아래에 한 줄 쓴다: "'진행'이라고 하시면 이 초안대로 시작합니다. 고칠 곳을 말씀하시면 고친 초안을 다시 보여 드립니다."
- 다음 단계를 스스로 시작하지 않는다. 사용자가 "진행"(또는 "그대로 해", "시작해")이라고 할 때만 시작한다.
- 사용자가 초안을 고치면 고친 초안을 다시 보여 주고 또 기다린다.
- "진행"하면 승인한 초안이 다음 단계의 "사용자 요청"이다. 그 단계가 끝나면 3에서 초안과 사용자가 고친 곳을 그대로 넘긴다.

## 웹에 붙일 요약 (사용자가 달라고 할 때만)

사용자가 설계를 웹 Claude와 따로 의논하고 싶다고 하면 아래 꼴로 짧게 만든다 (40줄 안). 저장소를 볼 수 없는 사람이 읽으므로 경로 대신 내용을 적는다.

```
## 웹에 붙일 요약 (<YYYY-MM-DD>, 브랜치 <이름>, 커밋 <짧은 해시>)
게임: 아주 약한 네크로맨서가 뼈와 머리뼈로 언데드를 소환하는 탑다운 2.5D 게임 (Godot 4.7, GDScript)
이번 단계: <요청 한 줄> → <결과 한 줄>
닿는 확정 규칙: <설계 문서에서 그대로 옮긴 몇 줄>
닿는 미정 항목: <그 줄>
의논할 것: <질문, 선택지마다 장단점, Claude의 추천과 근거>
```

- 웹에서 정한 것을 붙여 넣으면 `decide` 스킬로 기록한다 (출처는 "붙여 넣은 글").

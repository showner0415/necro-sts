# 먼 몬스터 판단 줄이기 (2026-11-14, 무리화 3b단계)

명령: `bash tools/godot.sh --headless --fixed-fps 60 --path . -s tests/balance/run_path_load.gd -- --far=24 --far_interval=<1 또는 4>`
장면: `tests/balance/stress_cave.tscn`. 3a 배치(쥐 32 + 멧돼지 8이 고리를 걷는 네크로맨서를 쫓음)에 먼 쥐 24마리를 더함: 굴 동쪽 벽 밖 x 2240부터 96px 격자(6열 × 4줄), 데이터 그대로 배회하고 맞히지 않는다. 고리의 가장 동쪽 x 1264에서 640px보다 멀다. 3초 기다린 뒤 30초 잼.
견주기: `--far_interval=1`은 판단 줄이기를 끈 것(모든 몬스터가 매 프레임 판단), `4`는 기본값(640px 밖이면 4프레임에 한 번). 두 조건을 번갈아 돌렸다.

## 주의: 이번 측정은 컴퓨터가 다른 프로그램(게임)을 함께 돌리는 중이었다

같은 조건(먼 쥐 없음)이 3a 때 3.8ms였는데 이번에는 7.9ms가 나왔다. 프레임 시간은 판마다 크게 흔들려서 두 조건의 차이를 가를 수 없었다. 컴퓨터가 한가할 때 다시 잰다.

| 판 | 간격 1 (끔) 평균 / 95% / 최대 | 간격 4 (켬) 평균 / 95% / 최대 |
|---|---|---|
| 1 | 7.16 / 13.25 / 195.65 | 5.46 / 9.17 / 40.94 |
| 2 | 7.24 / 14.74 / 116.99 | 7.60 / 14.76 / 122.75 |
| 3 | 5.72 / 9.83 / 54.01 | 5.24 / 8.53 / 117.88 |

바꾸기 전 코드(판단 줄이기를 넣기 전, 먼 쥐 24)로도 3판 쟀다: 평균 5.02 / 6.89 / 6.01ms (95% 7.33 / 12.46 / 13.39, 최대 90.54 / 212.01 / 163.31). 같은 흔들림 때문에 전후는 이 값 대신 위 표처럼 같은 코드에서 간격 1과 4를 번갈아 잰 값으로 견준다.

## 컴퓨터 부하와 상관없는 값: 프레임당 판단 횟수

| 간격 | 프레임당 판단 (`Monster.think_count`) |
|---|---|
| 1 (끔) | 64.0 |
| 4 (켬) | 44.7 |

- 64마리 중 먼 쥐 24마리의 판단이 1/4로 줄어 약 30% 적다 (24 → 약 6, 나머지 차이는 고리 반대편에서 잠깐 640px 밖으로 벌어진 추격 몬스터)
- 3a 구간표(2026-11-14_path_load.md)로는 판단(대상 찾기·시야·행동·능력치)이 몬스터 시간의 약 절반이다. 그래서 먼 몬스터가 많을수록 더 준다 (어림, 이번에는 시간으로 확인하지 못함)
- 3D 화면 밖 몸 숨기기는 헤드리스에서 3D 층을 붙이지 않아 이 측정에 들지 않는다
